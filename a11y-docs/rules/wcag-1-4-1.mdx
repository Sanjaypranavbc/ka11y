## What it checks

WCAG 1.4.1 requires that color is not used as the only visual means of conveying information, indicating an action, prompting a response, or distinguishing a visual element.

a11y's Node engine provides supplemental checks specifically for **inline links** and **form indicators** where color-only patterns are common.

## How it works

The `use-of-color.check.js` module performs a targeted scan of the DOM:

1.  **Inline Link Analysis**: Identifies links within text blocks (`p`, `li`, `td`, etc.) and compares their computed style with their parent element.
    *   **Visual Cues**: Checks for non-color differentiators such as `text-decoration: underline`, `border-bottom`, `outline`, `background-color` changes, or a `font-weight` delta of at least 100.
    *   **Luminance Comparison**: If no other cue is present, it calculates the RGB luminance difference. If the link is only distinguished by color, it flags a violation.
2.  **Form Heuristics**: Searches for required-field indicators that use color alone (e.g., "Fields in red are required") without a corresponding text label (like "required" or "*").
3.  **Status Heuristics**: Checks for status messages that rely solely on color keywords (e.g., "Status: Red") without a corresponding machine-readable status.

## Status Semantics

*   **FAIL**: High-confidence evidence of an inline link or form indicator using color as the only differentiator.
*   **INCOMPLETE**: Heuristic matches that require manual verification (e.g., complex charts or legends).

## Common violations

| Violation | Example |
|-----------|---------|
| Color-only links | Links in a paragraph that are blue but have no underline or bold weight. |
| Red for required | A form where required fields are indicated by red text only. |
| Color-coded status | A dashboard using green/yellow/red dots with no text labels or icons. |

## Suggested fix

Always provide an additional visual cue alongside color.

```css
/* FAILED - Color only */
a {
  color: blue;
  text-decoration: none;
}

/* PASSED - Underline added */
a {
  color: blue;
  text-decoration: underline;
}

/* PASSED - Weight difference */
p { color: black; font-weight: 400; }
a { color: blue; font-weight: 700; text-decoration: none; }
```

```html
<!-- FAILED -->
<p style="color: red;">Invalid input</p>

<!-- PASSED -->
<p style="color: red;"><span class="icon-error">!</span> Invalid input</p>
```

## Known limitations

*   **Shadow DOM**: Links inside shadow roots are currently not traversed by the custom check.
*   **Canvas/SVG**: Interactions on `<canvas>` or complex SVG diagrams are not audited for color-only logic.
*   **Hover States**: The check is static; it does not simulate hovers to see if an underline appears only on interaction.
