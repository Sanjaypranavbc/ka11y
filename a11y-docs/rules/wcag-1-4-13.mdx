## What it checks

When additional content appears on pointer hover or keyboard focus (tooltips, dropdown menus, popups), that content must satisfy three requirements:

| Requirement | Meaning |
|------------|---------|
| **Dismissible** | The user can dismiss the content without moving focus/pointer (e.g. via Escape key) |
| **Hoverable** | The pointer can move from the trigger onto the revealed content without it vanishing |
| **Persistent** | The content stays visible until the user intentionally removes hover/focus or dismisses it |

---

## How it works

This rule is the hardest to fully automate. a11y uses a best-effort heuristic scan:

```
Discover trigger candidates
  → elements with aria-expanded, data-tooltip, title, aria-describedby,
     aria-haspopup, .tooltip, .popover, .dropdown-toggle
        ↓
For each candidate (up to 20):
  1. Capture baseline popup count
  2. Hover the trigger (mouse.move to centre)
  3. Check whether popup count increased
  4. Wait briefly without user interaction → persistence check
  5. Press Escape — did the popup close?  → dismissible check
  6. Re-hover and move pointer toward popup location → hoverable check
        ↓
Detected popup + any failed check:
  - `FAILED` when popup evidence is certain (popup node captured)
  - `NEEDS_REVIEW` when evidence is ambiguous
Detected popup + all measurable checks pass → PASSED
Detected popup + some checks unknown (none failed) → NEEDS_REVIEW
No popups detected → PASSED
```

<Warning>
  Full automation of 1.4.13 is not possible. `NEEDS_REVIEW` still indicates
  manual verification is required, but unambiguous passing cases are now reported as `PASS`.
</Warning>

## Common violations

| Violation | Root cause | Fix |
|-----------|-----------|-----|
| Tooltip disappears on pointer move | CSS `:hover` only on trigger, not tooltip itself | Make the tooltip a sibling/child that also responds to `:hover` |
| Popup not dismissible by Escape | No `keydown` handler for Escape | Add `document.addEventListener('keydown', e => { if (e.key==='Escape') closePopup(); })` |
| Tooltip closes immediately when pointer moves toward it | Gap between trigger and tooltip is not hover-able | Add transparent padding/margin between trigger and popup |

---

## Suggested fix

```html
<!-- ❌ Tooltip only visible on trigger hover — vanishes when pointer moves -->
<button class="trigger">Hover me
  <span class="tooltip">This tooltip vanishes!</span>
</button>

<style>
.tooltip { display: none; }
.trigger:hover .tooltip { display: block; }
</style>

<!-- ✅ Tooltip stays visible when pointer moves into it -->
<style>
.tooltip { display: none; }
.trigger:hover .tooltip,
.tooltip:hover { display: block; }
/* Also add Escape key dismiss via JS */
</style>
```

## Known limitations

- **300 ms settle** may capture tooltips mid-transition; very fast fade-ins are measured before final paint.
- **Escape-to-dismiss** is scanned but stuck-open popups after Escape aren't reliably flagged (no post-Escape snapshot comparison).
- **Animation state** — if the popup relies on opacity/transform transitions rather than `display:none`, hover-off reliability can be miscategorised.
