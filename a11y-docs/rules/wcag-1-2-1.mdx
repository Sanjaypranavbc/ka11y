## What it checks

WCAG 1.2.1 requires that for prerecorded audio-only and prerecorded video-only media, a text alternative (transcript) is provided.

## How it works

a11y uses a dual-engine approach to detect media elements and search for associated transcripts:

### Node.js Engine (`audio-transcript.check.js`)
The Node engine performs a heuristic scan of the DOM for `<audio>` elements and searches for transcript evidence:
*   **Track Elements**: Checks for `<track>` children with `kind="captions|descriptions|subtitles"`.
*   **Nearby Links**: Scans ancestor containers for links containing "transcript" or "書き起こし" keywords.
*   **Figcaptions**: Checks for descriptive text in parent `<figure>` elements.
*   **Details Blocks**: Identifies collapsible `<details>` blocks that might contain the transcript.
*   **ARIA Associations**: Resolves `aria-describedby` attributes pointing to external transcript blocks.

### Python Engine (`MediaAuditor`)
The Python engine consumes the universal static snapshot and applies similar logic to both `<audio>` and `<video>` elements. It evaluates:
*   **Media Classification**: Distinguishes between audio-only and video-only based on the tag and `muted` attributes.
*   **Transcript Discovery**: Searches for nearby links and text blocks that likely serve as alternatives.
*   **Quality Engine**: In Japanese audits, it uses a dedicated Quality Engine to evaluate transcripts, using spaCy for tokenization and keyword detection.

## Common violations

| Violation | Example |
|-----------|---------|
| No transcript | An `<audio>` element with no associated text description or track. |
| Inaccessible link | A link labeled only as "audio.vtt" (F30 risk) without clear "transcript" text. |
| Missing alternative | A silent video-only clip without a text description of its visual content. |

## Suggested fix

Provide a clearly labeled transcript or a text alternative for all standalone media.

```html
<!-- Audio with transcript link -->
<figure>
  <audio src="interview.mp3" controls></audio>
  <figcaption>
    <a href="/transcripts/interview.html">View transcript for interview</a>
  </figcaption>
</figure>

<!-- Audio with ARIA description -->
<audio src="alert.mp3" aria-describedby="alert-text"></audio>
<p id="alert-text">A bell chime sounds to indicate the start of the session.</p>

<!-- Video-only with alternative -->
<video src="process.mp4" muted></video>
<details>
  <summary>View text alternative for process video</summary>
  <p>The video shows a 3D animation of the assembly line...</p>
</details>
```

## Known limitations

*   **Quality Equivalence**: The auditor checks for the *presence* of a transcript but cannot verify if the content is semantically equivalent to the media.
*   **External Links**: Links to transcripts on external domains are detected but their content is not fetched or verified.
*   **Cross-Origin Iframes**: Transcripts hidden inside cross-origin iframes are inaccessible to the auditors.
