## What it checks

WCAG 2.4.7 requires that any keyboard-operable user interface has a mode of operation where the keyboard focus indicator is visible. This is critical for sighted keyboard users to know which element they are currently interacting with.

a11y uses an interactive approach to verify that focusing an element actually results in a detectable visual change.

## How it works (Unified Pipeline)

The Unified Pipeline performs a high-fidelity visual delta simulation:

1.  **Baseline Capture**: `ElementContextExtractor` captures the initial computed styles (outline, box-shadow, border, background, etc.) of all focusable elements.
2.  **Interaction Simulation**: `InteractionStateRunner` natively simulates a `.focus()` action on each element.
3.  **Visual Delta Calculation**: The engine computes the difference in rendered CSS properties post-focus.
4.  **Policy Evaluation**: `Policy247` validates that at least one visual property changed significantly.

### False Positive Protection

*   **Custom Indicators**: Standard tools often fail elements that use `outline: none`, even if they have custom focus styles. a11y's pipeline correctly passes these elements if it detects changes in `box-shadow`, `background-color`, `border-color`, or even `transform` properties.
*   **Pseudo-Element Detection**: The simulation captures changes in `::before` and `::after` pseudo-elements, which are common locations for modern focus rings.
*   **Batched Execution**: Focus simulation is performed in optimized batches to ensure high performance even on pages with many interactive nodes.

## Node Engine Implementation (`focus-visible.check.js`)

The Node engine provides a secondary verification layer:
1.  **Sampled Interaction**: Sequentially focuses on a sample of up to 100 focusable elements.
2.  **Style Diffing**: Compares pre- and post-focus styles with an 80ms settle window to allow for CSS transitions.
3.  **Result Mapping**: Elements with no detectable change are flagged as violations.

## Status Semantics

*   **FAIL**: A focusable element shows no detectable change in computed visual properties when focused.
*   **PASS**: A clear visual change (e.g., outline, shadow, or color shift) is detected.

## Common violations

| Violation | Root cause |
|-----------|-----------|
| Hidden focus ring | CSS `outline: none` or `outline: 0` without a replacement style. |
| Low-contrast ring | A focus indicator that is too faint to be detected (also see [2.4.13 Focus Appearance](/rules/wcag-2-4-13)). |
| Zero-size indicators | Indicator is present in CSS but rendered at 0px width/height. |

## Suggested fix

Never remove the default focus ring without providing an equal or better visual alternative.

```css
/* FAILED - Focus indicator removed */
button:focus {
  outline: none;
}

/* PASSED - Custom focus ring */
button:focus {
  outline: none;
  box-shadow: 0 0 0 3px rgba(66, 153, 225, 0.6);
  border-color: #3182ce;
}

/* PASSED - Thematic change */
a:focus {
  background-color: yellow;
  color: black;
  text-decoration: underline;
}
```

## Known limitations

*   **Delayed Transitions**: CSS transitions with long delays (> 80ms) may not be fully captured by the diffing window.
*   **Animation States**: Focus indicators that rely on complex keyframe animations may produce inconsistent results in a single-snapshot diff.
