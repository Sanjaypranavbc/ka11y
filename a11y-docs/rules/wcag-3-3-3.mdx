## What it checks

WCAG 3.3.3 requires that if an input error is automatically detected and suggestions for correction are known, then the suggestions are provided to the user, unless it would jeopardize the security or purpose of the content.

a11y flags terse error messages that identify a problem but do not help the user fix it.

## How it works

The Node engine identifies existing error messages in the DOM and analyzes their content:

1.  **Error Discovery**: Locates error elements using `role="alert"`, `aria-live="assertive"`, `[aria-invalid="true"]`, or `[aria-errormessage]`.
2.  **Message Analysis**: Extracts the text of the error message and checks for "suggestion" patterns.
    *   **Terse Messages**: Flags messages consisting only of "Invalid", "Error", or "Required" as violations.
    *   **Guidance Patterns**: Searches for helpful keywords like "must", "should", "please", "example", "try", or specific format requirements (e.g., date formats, number ranges).
3.  **Result Mapping**: If an error is detected but provides no actionable guidance, it is flagged.

## Status Semantics

*   **FAIL**: An error message is present but is too terse or non-descriptive.
*   **PASS**: The error message includes a clear suggestion for how to correct the input.
*   **INCOMPLETE**: No error elements are currently present in the DOM (static scan).

## Common violations

| Violation | Example |
|-----------|---------|
| Terse error | A field marked with a red border and the single word "Invalid". |
| Ambiguous requirement | "Password too short" (doesn't say how many characters are needed). |

## Suggested fix

Provide specific, actionable instructions in every error message.

```html
<!-- FAILED -->
<div role="alert">Invalid date</div>

<!-- PASSED -->
<div role="alert">Please enter the date in MM/DD/YYYY format.</div>

<!-- FAILED -->
<div role="alert">Field is required.</div>

<!-- PASSED -->
<div role="alert">Email address is required to create an account.</div>
```

## Known limitations

*   **Runtime Errors**: Since this is a static scan, it can only evaluate errors already present in the DOM. Errors that only appear after a server-side submission may be missed.
*   **Contextual Complexity**: Suggestions that rely on complex domain logic (e.g., "That username is taken, try AcmeUser123") are hard to validate purely via pattern matching.
