## What it checks

WCAG 1.3.1 requires that information, structure, and relationships conveyed through presentation can be programmatically determined or are available in text. a11y's **Unified Accessibility Pipeline** provides context-aware auditing for structural relationships that standard linters often miss.

## How it works (Unified Pipeline)

The Unified Pipeline evaluates structural relationships by analyzing the entire page state:

1.  **Section Analysis**: `SectionAnalyzer` determines the macro-context of elements (e.g., `HEADER`, `FOOTER`, `DATA_TABLE`, `FORM_REGION`).
2.  **Semantic Mapping**: `SemanticRelationshipEngine` resolves ARIA pointers (`aria-describedby`, `aria-labelledby`) and native HTML groupings like `<fieldset>` and `<label>`.
3.  **Policy Evaluation**: `Policy131` uses this context to decide if structural information is properly exposed.

### False Positive Protection

*   **Context-Aware Orphans**: The pipeline avoids failing "orphaned" inputs (inputs without an explicit label) if they reside within a specifically identified macro-context like a `search` region or a `DATA_TABLE` where the relationship is implicitly clear but not strictly labeled.
*   **Recursive Fieldset Resolution**: The engine recursively traverses parent containers to find the correct `<fieldset>` and `<legend>`, ensuring that complex nested forms are audited accurately without double-counting violations.
*   **Aria-Controls/Owns Mapping**: Unlike static auditors that only check for attribute presence, the pipeline validates that the referenced IDs actually exist and establish a meaningful semantic bond.

## Key Audit Areas

Relationships are often established via text labels. a11y's Japanese support includes word-boundary-safe checks for common relationship indicators (e.g., "必須", "注記") and handles CJK-specific form patterns.

Columns: `page_url`, `tag`, `id`, `name`, `label_text`, `has_any_label`, `required`, `wcag_1_3_1_status`, `wcag_3_3_2_status`, `wcag_1_3_1_violation`

## Common violations

| Violation | Example |
|-----------|---------|
| Orphaned label | `<label>Name:</label> <input type="text">` (missing `for` attribute) |
| Missing fieldset | A group of radio buttons for "Shipping Method" without a wrapping `<fieldset>` and `<legend>`. |
| Placeholder-only | Using `placeholder="Search"` as the only way to identify an input. |
| Broken ARIA ref | `aria-describedby="msg-123"` where no element with `id="msg-123"` exists. |

## Suggested fix

Use semantic HTML elements and explicit ARIA relationships.

```html
<!-- FAILED -->
<div>
  <span>Username:</span>
  <input type="text" name="user">
</div>

<!-- PASSED (Explicit Label) -->
<div>
  <label for="user-field">Username:</label>
  <input type="text" id="user-field" name="user">
</div>

<!-- PASSED (Wrapping Label) -->
<label>
  Username:
  <input type="text" name="user">
</label>

<!-- PASSED (Grouped controls) -->
<fieldset>
  <legend>Choose a shipping method:</legend>
  <label><input type="radio" name="ship" value="std"> Standard</label>
  <label><input type="radio" name="ship" value="exp"> Express</label>
</fieldset>
```

## Known limitations

- **Heading hierarchy checks** live in axe-core; the Python pipeline does not validate H1→H2→H3 skip patterns beyond what axe reports.
- **Table header inference** — only axe's detection; no heuristic for `<div role="table">` ARIA grids.
- **F92 `role="presentation"` on structural elements** is axe-covered only.
