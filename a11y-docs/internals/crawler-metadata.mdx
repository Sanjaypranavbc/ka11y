## a11y-node — Crawler Architecture

a11y-node does **not** produce a persistent snapshot object. Instead, Puppeteer's `page` object is the live data source. Each rule calls `page.evaluate()` with its own JavaScript extractor, pulls exactly the fields it needs, and returns structured JSON. Interactive rules additionally use `page.keyboard`, `page.mouse`, `page.on()`, and `page.frames()`.

```
HTTP POST /api/v1/analyse-url
        │
        ▼
AccessibilityService
  ├── Puppeteer page.goto(url)
  ├── axe-core injection → axe.run()
  ├── runStaticChecks(page)       — 18 checks, page.evaluate() per check
  └── runInteractiveChecks(page)  — 6 checks, keyboard/focus/nav
```

**Shared page properties available to every check:**

| Property | Access Method | Description |
|----------|--------------|-------------|
| Full DOM | `document.querySelectorAll(selector)` | Any CSS selector |
| Computed styles | `window.getComputedStyle(el)` | All CSS computed values |
| Attributes | `el.getAttribute(name)` | Any HTML attribute |
| Text content | `el.textContent` / `el.innerText` | Visible + hidden text |
| Bounding rect | `el.getBoundingClientRect()` | Size and position |
| Page URL | `page.url()` / `window.location` | Current URL |
| Stylesheets | `document.styleSheets` | CSS rules (same-origin) |
| Active element | `document.activeElement` | Currently focused element |
| Frames | `page.frames()` | All iframes (same-origin) |

## a11y-python — Unified Pipeline (April 2026)

To permanently resolve false positives, `a11y-python` shifted from isolated single-purpose crawlers to a **Unified Context Pipeline** for core DOM rules (1.1.1, 1.3.1, 1.4.3, 1.4.5, 1.4.6, 1.4.11, 2.4.7, 2.4.13, 2.5.3, 2.5.8).

Instead of fragmented crawlers, `ElementContextExtractor` generates a single, deeply-nested `ElementContext` for every node on the page.

### ElementContextExtractor → `ElementContext`

The `ElementContext` acts as the single source of truth for the Decision Engine. It is composed of three primary sub-contexts:

#### 1. `SemanticContext`
| Field | Type | Description |
|-------|------|-------------|
| `tag_name`, `role` | `str` | Native identity and ARIA role |
| `section_type` | `SectionType` | Macro-context computed by `SectionAnalyzer` (e.g., `HEADER`, `FORM_REGION`, `DATA_TABLE`) |
| `ancestor_tags`, `ancestor_roles` | `List[str]` | Ordered list of all ancestors (DOM tree hierarchy) |
| `parent_tags`, `parent_roles` | `List[str]` | Immediate wrappers (used for quick grouping checks) |
| `is_in_labeled_control` | `bool` | True if the element is inside a `<button>`, `<a>`, or `[role="button"]` that provides its own label |
| `is_video_context` | `bool` | True if inside a video player (exempts thumbnails from 1.4.5) |
| `described_by_text` | `Optional[str]` | Resolved text from all IDs listed in `aria-describedby` |

#### 2. `VisualContext`
| Field | Type | Description |
|-------|------|-------------|
| `is_visible` | `bool` | Pre-filtered by computed style `display`, `visibility`, `opacity`, and `clip` |
| `bounding_box` | `BoundingBox` | Actual rendered box on screen |
| `computed_styles` | `Dict[str, str]` | Extracts `color`, `background-color`, `font-size`, `font-weight`, `opacity` |
| `resolved_background_color` | `str` | Traverses the DOM tree upward to compute the true, solid painted background color, resolving `rgba(0,0,0,0)` issues |
| `has_bg_image` | `bool` | True if the element utilizes a CSS background image |
| `cv_classification` | `Optional[str]` | Image classification (e.g., `logo`, `decorative`, `icon`, `complex`) |
| `ocr_text` | `Optional[str]` | Text detected within the image boundaries |
| `visible_label_text` | `Optional[str]` | The raw text nodes visually associated with the element |

#### 3. `InteractionContext`
| Field | Type | Description |
|-------|------|-------------|
| `is_focusable`, `tab_index` | `bool`, `int` | Keyboard reachability |
| `effective_clickable_bbox` | `BoundingBox` | Merges tiny native inputs with their wrapping `<label>` padding for accurate Target Size measurement |
| `adjacent_spacing_px` | `float` | Exact pixel distance to the nearest interactive element, computed via spatial bounds check |
| `has_focus_ring` | `bool` | Computed dynamically by `InteractionStateRunner` by extracting CSS deltas across main element and `::before`/`::after` pseudo-elements |
| `focus_ring_thickness_px`, `focus_ring_contrast` | `float` | Computed deltas of `box-shadow`, `border`, or `background-color` |

## a11y-python — Legacy Crawler Architecture

a11y-python uses a **Universal Discovery** architecture for the combined audit pipeline:

- `UniversalPageLoader` is the **Single Source of Truth** for page discovery and navigation.
- It performs one shared universal static crawl for seven rule families.
- `AsyncImageCrawler` and `RenderedLayoutCrawler` consume the **same discovered page inventory** from the universal loader.

```
POST /api/v1/combined
        │
        ▼
runner._run_job()
  ├── UniversalPageLoader (Discovery & Static Extraction)
  │     ├── List[DiscoveredURLs] ──┐
  │     └── PageSnapshot           │
  │           ├── forms            │
  │           ├── interactive      │
  │           ├── ...              │
  ├── SnapshotNormalizer           │
  │     └── Pydantic models        │
  ├── AsyncImageCrawler <──────────┘
  │     └── ImageMetadata (Screenshots/OCR)
  └── RenderedLayoutCrawler <──────┘
        └── PageSnapshots (Portrait/Landscape/Reflow)
```

The universal static path is where a11y-python now gets:

- same-origin iframe traversal
- open shadow-root traversal
- structured extraction warnings for cross-origin frames and partial failures
- sidecar provenance through `element_ref_id`, `selector`, and `frame_path`
- final-report `warning_details` with sampled frame metadata

Recent hardening on top of the universal path:

- `_merge_findings()` now prefers page-aware selector/target/ref evidence before HTML fallback
- OCR is budgeted on heavy pages through `crawler.performance.max_ocr_images_per_run`
- rendered hover and focus probes are bounded by `max_hover_candidates` and `max_focus_steps`
- CJK text-spacing overrides are built from `crawler.language.cjk_langs`
- config loading is cached and returned as defensive copies

Legacy crawler classes remain useful for direct debugging and compatibility, but the combined endpoint no longer needs seven separate static page loads.

### How universal crawler data is audited

The audit flow is intentionally **raw snapshot first, existing Pydantic models second, existing auditors third**.

This is the current production order:

1. `UniversalPageLoader.load()` does one Playwright session and extracts a `PageSnapshot`.
2. The raw snapshot is persisted as `universal_snapshot_raw.json`.
3. `SnapshotNormalizer.normalize()` converts each raw bucket into the existing Pydantic models.
4. The normalized snapshot is persisted as `universal_snapshot_normalized.json`.
5. `_run_python_stages()` creates one shared `snapshot_task` and passes it to every static auditor stage.
6. Each stage waits on the same normalized snapshot, calls the existing auditor unchanged, and receives structured audit rows back.
7. Stage-specific adapters convert those audit rows into unified combined findings.
8. The combined runner merges universal-static findings with image/OCR findings, rendered-layout findings, and `a11y-node` findings into `combined_report.json`.
9. Rich step logs capture crawler counts, auditor counts, finding counts, OCR-budget events, and warnings in `step_logs/combined_execution_steps.jsonl`.

### PageSnapshot structure

The raw snapshot emitted by `UniversalPageLoader` contains:

- `page_url`: The starting URL.
- `forms`, `interactive`, `target_sizes`, `moving_content`, `media`, `text_spacing`, `sensory`: Element-specific data buckets.
- `warnings`: Extraction logs (cross-origin frames, timeouts, detaching).
- `element_refs`: Global ID-to-element mapping for deduplication.
- `page_summaries`: Rollup of counts per URL (useful for dashboard progress bars).
- `pages_crawled`: Total count.

The universal crawler does **not** send raw dicts straight into the auditors.

`SnapshotNormalizer` is the compatibility boundary that:

- injects `page_url` into every normalized record
- validates payloads against the existing Pydantic models
- preserves `selector`, `element_ref_id`, and `frame_path` provenance for final findings
- records `normalization_error` warnings instead of crashing the whole run if one record is malformed

That means the auditors continue to operate on the same data contracts they already expected before the universal crawler existed.

### What the auditors receive in practice

The shared pattern looks like this:

```text
UniversalPageLoader
  -> PageSnapshot.forms / interactive / target_sizes / moving_content / media / text_spacing / sensory
  -> SnapshotNormalizer
  -> List[ExistingPydanticModel]
  -> ExistingAuditor.generate_audit_report(...)
  -> stage-specific *_to_findings(...)
  -> merged combined findings
```

The important detail is that the auditors are **not DOM-aware anymore at execution time** for these seven rule families. DOM traversal already happened in the universal crawl, and the auditors only reason over normalized records.

| Alt text | `el.getAttribute('alt')` | `ImageMetadata.alt` |
| ARIA label | `el.getAttribute('aria-label')` | `*.aria_label` |
| ARIA labelledby (resolved) | `el.getAttribute('aria-labelledby')` + `getElementById` at query time | `*.aria_labelledby` pre-resolved at crawl time |
| Role | `el.getAttribute('role')` | `*.role` |
| HTML snippet | `el.outerHTML.slice(0, N)` | `*.html_snippet` |
| Computed style | `getComputedStyle(el).property` | `*.css_*` fields or `RenderedLayoutCrawler` |
| Bounding rect | `el.getBoundingClientRect()` | `ElementSnapshot.rect.*` |
| Page URL | `page.url()` | `PageSnapshot.page_url` |
| Text content | `el.textContent.trim()` | `*.text` or `*.text_preview` |
| Required | `el.hasAttribute('required')` | `FormInputData.required` |
| Aria-required | `el.getAttribute('aria-required')` | `FormInputData.aria_required` |

<Info>
**Resolution strategy difference:** a11y-node resolves ARIA references (aria-labelledby, aria-describedby) at query time inside `page.evaluate()`. a11y-python resolves them during the crawl phase and stores the resolved text, so auditors receive pre-resolved values and never need to do DOM lookups.
</Info>
