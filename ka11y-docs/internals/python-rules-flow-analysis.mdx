## Architecture & Request Flow

### Current Production Path

The current production flow is the combined pipeline, not the older single-service `/api/v1/audit` model.

- One combined request fans out into `ka11y-node` and `ka11y-python`.
- `ka11y-python` now uses **one universal static crawl** for seven DOM rule families.
- `AsyncImageCrawler` now uses an **optimized single-session queue** for image capture, sharing a browser/context and crawl policy.
- `RenderedLayoutCrawler` still owns rendered, focus, hover, orientation, reflow, and resize scenarios.
- Every crawler now shares a central **Navigation Resilience** layer (DNS preflight + backoff) and a **Crawl Policy** (normalization + budgets).
- **Reporting:** Universal stages now hard-fail (mark as `error`) if the crawler extracts 0 pages, preventing false coverage reports.

### Current Python Stage Map

| Stage | Data source | Audit mode | Notes |
|------|-------------|------------|------|
| `form_audit` | Universal snapshot -> `FormInputData` | Static | Same-origin frames and open shadow roots supported through the universal crawl |
| `label_in_name` | Universal snapshot -> `InteractiveElementData` | Static | Provenance carried through `selector`, `element_ref_id`, `frame_path` |
| `pause_stop_hide` | Universal snapshot -> `MovingContentData` | Static | Supports `duration_known` and `applicability_exception=loading_indicator` |
| `target_size` | Universal snapshot -> `TargetSizeData` | Static | Same-origin iframe and shadow-root coverage inherited from universal crawl |
| `text_spacing` | Universal snapshot -> `TextSpacingData` | Static | Structural risk pass |
| `media_audit` | Universal snapshot -> `MediaElementData` | Static | Transcript/nearby-link checks on normalized records |
| `sensory_audit` | Universal snapshot -> `SensoryElementData` | Static | Language-aware, including JP/CJK handling |
| `image_audit` | `AsyncImageCrawler` + OCR | Multimodal | OCR is now budgeted and logged for large pages |
| `rendered_layout_audit` | `RenderedLayoutCrawler` | Rendered | Hover/focus path hardened against stale or invisible boxes |

### Recent Hardening Additions

| Area | Current behavior |
|------|------------------|
| Zero-coverage guard | Universal stages mark themselves `error` if `pages_crawled == 0` instead of emitting false passes |
| Navigation Resilience | Centralized `navigate_with_resilience` (DNS preflight, backoff, retry) shared across all crawlers |
| Crawl Policy | `CrawlPolicy` centralizes URL normalization, same-origin rules, and page/link budgets |
| Image session queue | `AsyncImageCrawler` uses one browser/context for multi-page crawls instead of recursive launches |
| Universal warnings | Cross-origin and failed-frame warnings are sampled into `warning_details` in `combined_report.json` |

### Localization and Language Routing

The combined request `lang` now feeds both stacks, but the Python output contract is still split by responsibility:

- `criterion_name` is localized through the shared i18n loader
- `suggested_fix` is localized through the same shared `rules.yml` + locale overlay path
- `reason` is only localized when the emitting Python auditor/evaluator provides localized text

Practical outcome today:

- Japanese combined runs get JP-aware OCR and JP-aware sensory/text-spacing heuristics where implemented
- Python `reason` strings are still mixed: some newer or config-driven auditors localize, while several older converters remain English
- Node output is more fully localized than Python output at the finding-text layer

### 1.1.1 — Non-text Content (Level A)
**Check:** `alttext.py`

#### Flowchart
```mermaid
flowchart TD
    START["Image Metadata + OCR"] --> CLASS{"Classification?"}
    CLASS -- Decorative --o DEC["alt = empty?"]
    CLASS -- Informative --o INF["Alt matches OCR?"]
    CLASS -- Logo --o LOG["Alt contains 'logo'/'home'?"]
    CLASS -- Icon --o ICO["Alt describes action/icon?"]
    CLASS -- Button --o BTN["Alt describes action?"]
    
    DEC -- Yes --> PASS["PASS"]
    DEC -- No --> FAIL1["FAIL: 1.1.1 Decorative needs empty alt"]
    
    INF -- Match --> PASS
    INF -- No Match --> FAIL2["FAIL: 1.1.1 OCR words missing in alt"]
    
    LOG -- Yes --> PASS
    LOG -- No --> FAIL3["FAIL: 1.1.1 Logo needs 'logo'/'home' text"]
    
    ICO -- Yes --> PASS
    ICO -- No --> FAIL4["FAIL: 1.1.1 Icon needs purpose/qualifier"]
    
    BTN -- Yes --> PASS
    BTN -- No --> FAIL5["FAIL: 1.1.1 Button needs action word"]
```

#### Cases Covered
| Case | Detection Method |
|------|-----------------|
| Decorative alt transparency | Strictly enforces `alt=""` |
| Informative content parity | OCR word-match (3+ chars) |
| Branding logotypes | Keyword check ('logo', 'home') |
| Social/Action icons | "Brand icon" or "Close" keyword match |
| Button purpose | Action word regex (`_BUTTON_ACTION_WORDS`) |

#### Cases Missed / False Negative Risks
| Case | Why missed |
|------|-----------|
| Short OCR tokens | Tokens < 3 characters are ignored to avoid noise |
| Complex diagrams | Heuristic only checks if alt is non-empty |
| Image-map areas | Not explicitly audited in `alttext.py` |

### 1.4.3 — Contrast (Minimum) (Level AA)
**Check:** `contrast_analyser.py` (Multimodal)

#### Flowchart
```mermaid
flowchart TD
    IMG["Image of Text / Element Crop"] --> SEG["Segmentation (Otsu)"]
    SEG --> L["Calculate Relative Luminance (L1, L2)"]
    L --> SIZE{"Large Text?"}
    
    SIZE -- "Yes (>=24px/18.5px+B)" --> L30{"Ratio >= 3.0:1?"}
    SIZE -- "No" --> L45{"Ratio >= 4.5:1?"}
    
    L30 -- "Yes" --> PASS["PASS"]
    L30 -- "No" --> FAIL1["FAIL: 1.4.3 Contrast below 3:1"]
    
    L45 -- "Yes" --> PASS
    L45 -- "No" --> FAIL2["FAIL: 1.4.3 Contrast below 4.5:1"]
```

#### Cases Covered
| Case | Detection |
|------|-----------|
| Text in images (OCR-led) | `analyze_text_region` |
| Large text exemption | 24px regular / 18.5px bold threshold |
| Color-space accuracy | sRGB to Linear luminance conversion |

#### Cases Missed
| Case | Why |
|------|-----|
| Complex backgrounds | Segmentation (Otsu) may fail on high-noise gradients |
| Multi-color text | Color averaging doesn't catch per-character contrast |
