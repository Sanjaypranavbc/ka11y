## Architecture & Request Flow (Updated April 2026)

### The Unified Accessibility Pipeline

To eliminate false positives caused by evaluating elements in a vacuum, the Python engine was re-architected. Instead of individual rule crawlers (e.g., `LabelInNameAuditor` or `TargetSizeAuditor`) running in isolation, the new architecture uses a **Centralized Context Pipeline**.

1.  **ElementContextExtractor:** A single, unified Playwright script extracts the entire DOM, including computed styles, ARIA attributes, and bounding boxes.
2.  **Semantic Enrichment:**
    *   **SectionAnalyzer:** Determines the macro-context (e.g., `HEADER`, `FORM_REGION`, `DATA_TABLE`).
    *   **SemanticRelationshipEngine:** Resolves ARIA pointers (`aria-describedby`, `aria-labelledby`) and native HTML group mechanics (`<fieldset>`, `<label>`).
3.  **Interaction Simulation:** The `InteractionStateRunner` natively simulates interactions (like `.focus()`) and captures the delta in rendered CSS properties (like `box-shadow` or `background-color`) to prove visible state changes.
4.  **Decision Engine**: Evaluates the rich `ElementContext` against registered `WCAGPolicy` classes:
    *   **Policy111**: 1.1.1 Non-text Content (with functional redundancy check)
    *   **Policy131**: 1.3.1 Info and Relationships (context-aware orphaned input check)
    *   **Policy143 / 146**: 1.4.3 / 1.4.6 Contrast (Minimum/Enhanced) with dynamic font-size thresholds
    *   **Policy145**: 1.4.5 Images of Text (OCR-backed)
    *   **Policy1411**: 1.4.11 Non-text Contrast (rendered boundary check)
    *   **Policy247 / 2413**: 2.4.7 / 2.4.13 Focus Visible and Appearance (visual delta simulation)
    *   **Policy253**: 2.5.3 Label in Name (NFC-normalized substring match)
    *   **Policy258**: 2.5.8 Target Size (effective clickable area calculation)
5.  **Evidence Formatter**: Maps the internal pipeline `RuleVerdict` back to the legacy JSON schema expected by the frontend.

### Rule-by-Rule Analysis

---

### 1.1.1 — Non-text Content (Level A)
**Engine:** Unified Pipeline (`Policy111`)

#### Flowchart
```mermaid
flowchart TD
    START["ElementContext (Semantics + Visual)"] --> EX{"Decorative or Presentation?"}
    EX -- Yes --> PASS_DEC["Pass if no alt name"]
    EX -- No --> FR{"Functional Redundancy?"}
    
    FR -- "Inside labeled button/link" --> PASS_FR["PASS: Specific alt not required"]
    FR -- "Independent image" --> NM{"Missing Accessible Name?"}
    
    NM -- Yes --> FAIL["FAIL: Missing alt text"]
    NM -- No --> CLASS{"Image Classification"}
    
    CLASS -- Logo --> LOG["Validate 'logo' or 'brand' keywords"]
    CLASS -- Icon --> ICO["Validate minimum length and word characters"]
    CLASS -- Informative --> INF["Validate informative name against OCR text"]
```

**Key False Positive Protections:**
- Uses `SemanticRelationshipEngine` to detect if an image is inside an already-labeled `<button>` or `<a>`. If so, it passes as functionally redundant.
- Uses word-boundary regex (`\b`) to validate OCR text, preventing naive substring matches (e.g., passing "research" when OCR found "search").

---

### 1.3.1 — Info and Relationships (Level A)
**Engine:** Unified Pipeline (`Policy131`)

**Key False Positive Protections:**
- Checks the macro-context (e.g., `DATA_TABLE`, `FORM_REGION`) provided by `SectionAnalyzer` before failing orphaned inputs.
- Validates relationships through `aria-describedby` or parent `fieldset` resolution provided by `SemanticRelationshipEngine`.

---

### 1.4.3 & 1.4.6 — Contrast (Minimum & Enhanced) (Level AA / AAA)
**Engine:** Unified Pipeline (`Policy143`, `Policy146`, `ContrastEngine`)

**Key False Positive Protections:**
- **Dynamic Thresholds:** Uses `getComputedStyle` to check `font-size` and `font-weight`. Automatically drops the requirement to `3.0:1` (AA) or `4.5:1` (AAA) for large text.
- **Classification Exemptions:** Ignores images classified as `logo` or `decorative`, complying with WCAG exemptions.
- **Transparent Backgrounds:** Correctly identifies `rgba(..., 0)` backgrounds and marks them as `NEEDS_REVIEW` instead of blindly failing a 1:1 ratio against the DOM body.

---

### 1.4.5 — Images of Text (Level AA)
**Engine:** Unified Pipeline (`Policy145`)

**Key False Positive Protections:**
- **Contextual Exemptions:** Automatically bypasses elements classified as `logo`, `decorative`, `complex`, or `chart`. 
- **Video Thumbnails:** Exempts elements residing inside a `video_context` wrapper (e.g., video posters with burned-in subtitles).
- **Dynamic Reasons:** Fails with a snippet of the exact text detected by OCR, allowing developers to immediately verify the claim.

---

### 2.4.7 — Focus Visible (Level AA)
**Engine:** Unified Pipeline (`Policy247`, `InteractionStateRunner`)

**Key False Positive Protections:**
- **Visual Delta Simulation:** Legacy engines failed elements that used `outline: none`. The new pipeline explicitly `.focus()`es the element and computes the delta in rendered CSS properties. If `box-shadow`, `background-color`, or `border-color` changes upon focus, it correctly passes the rule.

---

### 2.5.3 — Label in Name (Level A)
**Engine:** Unified Pipeline (`Policy253`)

**Key False Positive Protections:**
- Evaluates the **Visible Label** (the raw text nodes visible to the user) against the computed **Accessible Name** (resolving `aria-label`, `aria-labelledby`, `alt`, etc.).
- Normalizes punctuation and casing. Validates that the visible label is a contiguous substring of the accessible name, properly supporting legally compliant variations (e.g., Visible: "Submit", ARIA: "Submit Form").

---

### 2.5.8 — Target Size (Level AA)
**Engine:** Unified Pipeline (`Policy258`)

**Key False Positive Protections:**
- **Effective Clickable Area:** Native `<input type="radio">` tags are often 12x12px, which fails the 24x24px rule. However, the `ElementContextExtractor` merges the bounding box of the input with its parent `<label>` or `<button>`. The rule evaluates this *effective* area, eliminating false positives on properly wrapped inputs.
- **UA-Controlled:** Accurately exempts native inputs where CSS `appearance` has not been overridden.
    DEC -- No --> FAIL1["FAIL: 1.1.1 Decorative needs empty alt"]
    
    INF -- Match --> PASS
    INF -- No Match --> FAIL2["FAIL: 1.1.1 OCR words missing in alt"]
    
    LOG -- Yes --> PASS
    LOG -- No --> FAIL3["FAIL: 1.1.1 Logo needs 'logo'/'home' text"]
    
    ICO -- Yes --> PASS
    ICO -- No --> FAIL4["FAIL: 1.1.1 Icon needs purpose/qualifier"]
    
    BTN -- Yes --> PASS
    BTN -- No --> FAIL5["FAIL: 1.1.1 Button needs action word"]
```

#### Cases Covered
| Case | Detection Method |
|------|-----------------|
| Decorative alt transparency | Strictly enforces `alt=""` |
| Informative content parity | OCR word-match (3+ chars) |
| Branding logotypes | Keyword check ('logo', 'home') |
| Social/Action icons | "Brand icon" or "Close" keyword match |
| Button purpose | Action word regex (`_BUTTON_ACTION_WORDS`) |

#### Cases Missed / False Negative Risks
| Case | Why missed |
|------|-----------|
| Short OCR tokens | Tokens < 3 characters are ignored to avoid noise |
| Complex diagrams | Heuristic only checks if alt is non-empty |
| Image-map areas | Not explicitly audited in `alttext.py` |
