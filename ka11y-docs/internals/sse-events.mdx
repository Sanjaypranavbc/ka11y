<Info>
  Endpoint: `GET /api/v1/combined/{job_id}/stream` · Media type: `text/event-stream`
</Info>

## Wire format

Every event follows the standard SSE framing:

```
event: <event_type>\n
data: <json_object>\n
\n
```

A blank line separates events. The client reads `event.type` and `JSON.parse(event.data)`.

```javascript
const es = new EventSource(`/api/v1/combined/${jobId}/stream`);

es.addEventListener("stage_complete", (e) => {
  const { stage_name, findings_count } = JSON.parse(e.data);
  console.log(`${stage_name} → ${findings_count} findings`);
});
```

## Event catalog

### `stage_start`

Emitted when a pipeline stage begins execution.

```json
{
  "stage_name": "form_audit",
  "started_at": "2025-11-04T10:22:18.412Z"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `stage_name` | string | Internal stage identifier (see [Stage names](#stage-names)) |
| `started_at` | string (ISO-8601) | UTC timestamp |

---

### `stage_complete`

Emitted when a stage finishes without error.

```json
{
  "stage_name": "form_audit",
  "completed_at": "2025-11-04T10:22:21.903Z",
  "findings_count": 7
}
```

| Field | Type | Description |
|-------|------|-------------|
| `stage_name` | string | Stage identifier |
| `completed_at` | string (ISO-8601) | UTC timestamp |
| `findings_count` | number | Number of findings (violations + passes) from this stage |

---

### `stage_error`

Emitted when a stage throws an unhandled exception. The pipeline continues with remaining stages.

```json
{
  "stage_name": "axe_core",
  "error": "Connection refused: http://node:3000"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `stage_name` | string | Stage that failed |
| `error` | string | Exception message |

<Note>
  A `stage_error` does **not** mean the whole job failed. Other stages may still
  complete successfully. The job only transitions to `failed` when every stage
  errors out and there are zero findings to report.
</Note>

---

### `job_state`

Sent **once** to clients that connect after the job has already started. Provides a snapshot of all stages seen so far so the UI can reconstruct progress without missing earlier events.

```json
{
  "current_stage": "pause_stop_hide",
  "stages": [
    {
      "name": "axe_core",
      "status": "completed",
      "started_at": "2025-11-04T10:22:14.000Z",
      "completed_at": "2025-11-04T10:22:17.800Z",
      "findings_count": 12
    },
    {
      "name": "image_audit",
      "status": "completed",
      "started_at": "2025-11-04T10:22:14.000Z",
      "completed_at": "2025-11-04T10:22:21.200Z",
      "findings_count": 3
    },
    {
      "name": "form_audit",
      "status": "completed",
      "started_at": "2025-11-04T10:22:21.500Z",
      "completed_at": "2025-11-04T10:22:24.100Z",
      "findings_count": 7
    },
    {
      "name": "pause_stop_hide",
      "status": "running",
      "started_at": "2025-11-04T10:22:24.300Z"
    }
  ]
}
```

| Field | Type | Description |
|-------|------|-------------|
| `current_stage` | string | Most recent stage that started |
| `stages` | StageRecord[] | All stages seen so far with their current status |

**`StageRecord` shape:**

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Stage identifier |
| `status` | `"running"` \| `"completed"` \| `"error"` | Current state |
| `started_at` | string (ISO-8601) | When the stage began |
| `completed_at` | string (ISO-8601) | Present when `status` is `completed` or `error` |
| `findings_count` | number | Present when `status` is `completed` |
| `error` | string | Present when `status` is `error` |

---

### `job_complete`

Emitted after all stages finish and the report has been persisted to disk. The full report is **not** included in the SSE payload — fetch it via `GET /combined/{job_id}` to avoid sending large JSON through the event stream.

```json
{
  "job_id": "a1b2c3d4-...",
  "summary": {
    "total_findings": 34,
    "violations": 18,
    "needs_review": 4,
    "passes": 12,
    "by_severity": {
      "critical": 2,
      "high": 9,
      "medium": 5,
      "low": 2
    }
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `job_id` | string | UUID of the completed job |
| `summary` | object | High-level counts from `CombinedReport.summary` |

After receiving this event the client should:
1. Close the `EventSource`
2. `GET /api/v1/combined/{job_id}` to retrieve the full report

---

### `job_failed`

Emitted when the job transitions to `failed` (all stages errored, nothing to report).

```json
{
  "job_id": "a1b2c3d4-...",
  "error": "All audit stages failed. Check server logs for details."
}
```

| Field | Type | Description |
|-------|------|-------------|
| `job_id` | string | UUID of the failed job |
| `error` | string | Aggregated failure reason |

## Heartbeat

Every **25 seconds** of silence the server sends a keepalive comment:

```
: keepalive
```

This prevents proxies and load balancers from closing idle connections. The browser `EventSource` API ignores comment lines — no client-side handling needed.

## Late-connect behaviour

```
Client connects AFTER job completes
         │
         ▼
  job status = completed → send "job_complete" immediately, close stream
  job status = failed    → send "job_failed" immediately, close stream
  job status = running   → send "job_state" snapshot, then continue live events
  job status = pending   → wait in queue (no snapshot to send yet)
```

## Error handling

```javascript
const es = new EventSource(`/api/v1/combined/${jobId}/stream`);

// Terminal events — close the stream
es.addEventListener("job_complete", (e) => {
  es.close();
  fetchFullReport(jobId);
});
es.addEventListener("job_failed", (e) => {
  es.close();
  const { error } = JSON.parse(e.data);
  showError(error);
});

// Network error or proxy timeout — fall back to polling
es.onerror = () => {
  es.close();
  startPollingFallback(jobId);
};

function startPollingFallback(jobId) {
  const id = setInterval(async () => {
    const res = await fetch(`/api/v1/combined/${jobId}`);
    const data = await res.json();
    if (data.status === "completed" || data.status === "failed") {
      clearInterval(id);
      handleResult(data);
    }
  }, 3000);
}
```
