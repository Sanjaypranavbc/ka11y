## Current Config Layers

The crawler stack currently has **four** practical configuration layers, and they do not all do the same job:

| Layer | Source | What it controls |
|------|--------|------------------|
| Base runtime config | `ka11y/config/config.yml` | crawler defaults for standalone/direct runs |
| Environment | shell / Docker env vars | service wiring such as `NODE_BASE_URL` |
| API request payload | `POST /api/v1/combined/` body | per-job behavior such as `lang`, `max_depth`, and `run_*` stage toggles |
| Live test plan YAML | `ka11y-python/scripts/live_stage_plan.*.yml` | test harness inputs for real-site validation, not application runtime defaults |

This distinction matters because the redesign docs mention language packs and site profiles, but that part is still **planned architecture**, not the current runtime config system.

### What is implemented today

- `config.yml` for crawler and output defaults
- `NODE_BASE_URL` for Python → Node service routing
- per-request `lang` and `run_*` booleans on the combined API
- live-run plan YAML for real-site validation scenarios

### What is not implemented yet

- runtime-resolved `site-profiles/*.yml`
- `languages/{lang}.yml` feeding crawler behavior directly at runtime
- a cross-service config loader that automatically merges global + language + site overrides

## Config file

ka11y-python reads `ka11y/config/config.yml` at startup via `ka11y/utils/config_loader.py`.

```yaml
# ka11y/config/config.yml

input:
  url:        "https://example.com"   # Default URL for CLI / standalone runs
  max_depth:  0                        # 0 = single page; >0 = recursive crawl depth
  output_dir: "crawled_images"         # Base output directory (relative to CWD)

directories:
  - "informative"
  - "decorative"
  - "functional"
  - "functional/buttons"
  - "functional/icons"
  - "functional/logos"
  - "functional/images"
  - "complex"
  - "complex/charts"
  - "complex/emojis"

ocr:
  base_folder:     "text_detected"
  contrast_folder: "contrast"
  categories:
    button_text:        "button_text"
    informational_text: "informational_text"
    logo_text:          "logo_text"
    with_text:          "with_text"

crawler:
  include_data_uris: false   # Include base64 data: URIs in image crawl
  include_invisible: false   # Include elements with visibility:hidden / display:none
  scroll_passes:     3       # Number of scroll passes to trigger lazy-loaded content

crawl_browser:
  width:  1920               # Playwright viewport width (CSS px)
  height: 1080               # Playwright viewport height (CSS px)
```

### Loading the config

```python
from ka11y.utils.config_loader import load_config

config = load_config()                           # Default path
config = load_config("path/to/config.yml")       # Custom path
```

The `load_config()` function uses `yaml.safe_load` — no Python execution in the YAML file.

## Environment variables

Set these in your shell, `.env` file, or `docker-compose.yml` `environment:` block.

| Variable | Default | Description |
|----------|---------|-------------|
| `NODE_BASE_URL` | `http://localhost:3000` | Base URL of the ka11y-node service |
| `PYTHONUNBUFFERED` | — | Set to `"1"` in Docker to get real-time log output |

### NODE_BASE_URL

The Python service uses `NODE_BASE_URL` to reach the ka11y-node service during combined audits and live matrix runs.

```bash
# Local dev (Node running on host)
NODE_BASE_URL=http://localhost:3000

# Docker Compose (uses Docker internal DNS)
NODE_BASE_URL=http://node:3000
```

## Config reference by section

### `input`

Used only when running the pipeline directly (not through the API). API requests supply these values in the request body.

| Key | Type | Description |
|-----|------|-------------|
| `url` | string | Target URL |
| `max_depth` | int | Crawl depth (0 = single page) |
| `output_dir` | string | Base directory for output files |

### `directories`

Sub-directories created under `output_dir` for storing classified images. Matches the image classifier's output categories.

### `ocr`

Controls where OCR intermediate files are stored.

| Key | Description |
|-----|-------------|
| `base_folder` | Sub-directory for detected text images |
| `contrast_folder` | Sub-directory for contrast-adjusted images |
| `categories.*` | Maps classification names to folder names |

### `crawler`

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `include_data_uris` | bool | `false` | When `true`, images encoded as `data:` URIs are crawled |
| `include_invisible` | bool | `false` | When `true`, off-screen and hidden elements are included |
| `scroll_passes` | int | `3` | Playwright scrolls the page this many times to trigger lazy-load |

### `crawl_browser`

Playwright viewport dimensions. Use `1920×1080` (desktop) or `375×812` (mobile) to test at different breakpoints.

## Combined API Request Config

For the combined endpoint, the request body is the **real per-audit config layer**.

Important fields:

| Field | Effect |
|------|--------|
| `url` | target page |
| `max_depth` | same-origin crawl depth |
| `wcag_level` | post-merge WCAG filtering |
| `lang` | localized output language plus some language-aware heuristics |
| `run_*` booleans | stage enable/disable switches |

If a `run_*` field is omitted, the current `CombinedRequest` defaults apply, which means the stage remains enabled.

That is why the full-stack live plan can leave all `run_*` fields out and still run with every rule family turned on.

## Live Runner Plan Config

`ka11y-python/scripts/live_stage_audit.py` uses YAML plan files as a **test harness config**, not as server runtime config.

Example plan fields:

| Field | Meaning |
|------|---------|
| `id` | stable run identifier |
| `url` | live or staged URL |
| `lang` | per-run request language |
| `wcag_level` | per-run WCAG filtering |
| `max_depth` | crawl depth for that run |
| `run_*` | optional per-run stage overrides |
| `expected_features` | human-readable coverage intent |
| `expectations` | machine-checked validation rules for the run |

Current plan files:

| Plan | Purpose |
|------|---------|
| `live_stage_plan.public_matrix.yml` | focused universal-static real-site validation |
| `live_stage_plan.public_full_stack.yml` | real-site validation with all combined-rule defaults enabled |

The live runner also respects `--node-base-url` or `NODE_BASE_URL`, so the same plan file can be used locally, in Docker, or against a remote node service.

## Language and Japanese Behavior Today

Current behavior is split across request config and code:

- `lang: "ja"` in the combined request localizes the output and routes Japanese-aware behavior where already implemented
- some Japanese/CJK heuristics still live in auditor code, especially sensory/media logic
- the universal crawler itself is language-agnostic except for data collection and exception markers

So today, Japanese support is **partly request-configured and partly code-driven**.

The redesign target in `CRAWLER_ANALYSIS.md` is to move more of that behavior into explicit language config assets, but the docs should not imply that this migration is already complete.

## Adding a new config key

1. Add the key to `ka11y/config/config.yml`.
2. Import `config` in your module:
   ```python
   from ka11y.utils.config_loader import config
   value = config["your_section"]["your_key"]
   ```
3. Add a sensible default — `config_loader.py` uses `yaml.safe_load` and will return `None` for missing keys unless you guard with `.get()`.

## Logger

Configured in `ka11y/config/logger.py`. Each module creates a tagged logger:

```python
from ka11y.config.logger import setup_logger

logger = setup_logger(name="KAC", tag="my_module")
logger.info("Starting up")
```

The `tag` appears in log output to identify the source module.
