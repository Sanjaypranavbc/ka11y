## アーキテクチャと要求フロー

### 現在の本番経路

現在の本番フローは、旧 `/api/v1/audit` 単体サービスではなく **combined パイプライン** です。

- 1 件の combined リクエストが `ka11y-node` と `ka11y-python` に分岐する
- `ka11y-python` は 7 つの DOM ルール群に対して **1 回の universal static crawl** を共有する
- `AsyncImageCrawler` は画像取得、OCR、コントラスト、画像監査を担当する
- `RenderedLayoutCrawler` は表示方向、リフロー、テキストサイズ変更、ホバー、フォーカス系の評価を担当する
- 最終レポートはマージ、重複排除、warning 付与を行い `combined_report.json` として保存される

    B --> C["ka11y-node: axe-core + custom checks"]

    subgraph "Python クローラー分岐"

### 現在の Python ステージ構成

| ステージ | データソース | 監査モード | 備考 |
|------|-------------|------------|------|
| `form_audit` | Universal snapshot -> `FormInputData` | Static | same-origin iframe と open shadow root を universal crawl から継承 |
| `label_in_name` | Universal snapshot -> `InteractiveElementData` | Static | `selector`、`element_ref_id`、`frame_path` の来歴を保持 |
| `pause_stop_hide` | Universal snapshot -> `MovingContentData` | Static | `duration_known` と `applicability_exception=loading_indicator` に対応 |
| `target_size` | Universal snapshot -> `TargetSizeData` | Static | iframe / shadow-root のカバレッジを継承 |
| `text_spacing` | Universal snapshot -> `TextSpacingData` | Static | 構造リスク判定 |
| `media_audit` | Universal snapshot -> `MediaElementData` | Static | transcript / nearby-link 判定 |
| `sensory_audit` | Universal snapshot -> `SensoryElementData` | Static | 日本語 / CJK を含む言語対応 |
| `image_audit` | `AsyncImageCrawler` + OCR | Multimodal | OCR には予算上限があり、大規模ページでも段階的に処理 |
| `rendered_layout_audit` | `RenderedLayoutCrawler` | Rendered | hover / focus の失敗モードを強化済み |

### 直近の強化点

| 領域 | 現在の挙動 |
|------|------------------|
| Universal warnings | cross-origin / failed-frame warning を `warning_details` にサンプリングして出力 |
| Merge dedup | `runner._merge_findings()` は HTML フォールバックより selector / target / ref を優先 |
| OCR budget | `crawler.performance.max_ocr_images_per_run` が OCR 対象数を制限し、選択 / スキップ数をログ出力 |
| Rendered limits | `crawler.performance.max_focus_steps` と `crawler.performance.max_hover_candidates` で探索量を制御 |
| CJK text spacing | `crawler.language.cjk_langs` が日本語など CJK 向け spacing override CSS を決定 |
| Config loading | `load_config()` はキャッシュされるが、防御的コピーを返して共有状態の破壊を防ぐ |

### 日本語化と言語ルーティング

combined リクエストの `lang` は Node と Python の両方に渡されますが、Python 側の finding 文字列は責務によって挙動が分かれます。

- `criterion_name` は共有 i18n ローダーから日本語化される
- `suggested_fix` も同じ shared `rules.yml` + locale overlay から日本語化される
- `reason` は各 Python オーディター / evaluator が返す文言に依存する

現在の実務上の挙動:

- 日本語監査では OCR や sensory / text-spacing 系の一部ヒューリスティックが `lang=ja` に追従する
- Python の `reason` はまだ混在しており、古い converter は英語のままのものがある
- finding テキスト全体の日本語化は、現時点では Python より Node の方が進んでいる

### 1.1.1 — 非テキストコンテンツ (レベル A)
**チェックファイル:** `alttext.py`

#### フローチャート
```mermaid
flowchart TD
    START["画像メタデータ + OCR"] --> CLASS{"分類は？"}
    CLASS -- 装飾的 --o DEC["alt = 空？"]
    CLASS -- 情報提供 --o INF["AltはOCRと一致？"]
    CLASS -- ロゴ --o LOG["Altに 'logo'/'home' を含む？"]
    CLASS -- アイコン --o ICO["Altは役割/目的を記述？"]
    CLASS -- ボタン --o BTN["Altはアクションを記述？"]
    
    DEC -- はい --> PASS["合格 (PASS)"]
    DEC -- いいえ --> FAIL1["不合格: 1.1.1 装飾的な画像には空のaltが必要"]
    
    INF -- 一致 --> PASS
    INF -- 不一致 --> FAIL2["不合格: 1.1.1 OCR検出語がaltに含まれていない"]
    
    LOG -- はい --> PASS
    LOG -- いいえ --> FAIL3["不合格: 1.1.1 ロゴには 'logo'/'home' テキストが必要"]
    
    ICO -- はい --> PASS
    ICO -- いいえ --> FAIL4["不合格: 1.1.1 アイコンには目的や役割が必要"]
    
    BTN -- はい --> PASS
    BTN -- いいえ --> FAIL5["不合格: 1.1.1 ボタンにはアクションを示す語が必要"]
```

#### 対象ケース
| ケース | 検出方法 |
|------|-----------------|
| 装飾的なaltの透明性 | `alt=""` を厳格に適用 |
| 情報提供画像の整合性 | OCR単語一致 (3文字以上) |
| ブランド・ロゴタイプ | キーワードチェック ('logo', 'home') |
| ソーシャル/アクションアイコン | "Brand icon" または "Close" などのキーワード一致 |
| ボタンの目的 | アクション語の正規表現 (`_BUTTON_ACTION_WORDS`) |

#### 未対応 / 誤検出(偽陰性)のリスク
| ケース | 理由 |
|------|-----------|
| 短いOCR単語 | ノイズ回避のため3文字未満は無視される |
| 複雑な図表 | altが空でないかどうかのヒューリスティックのみ |
| イメージマップ領域 | `alttext.py` では明示的に監査されていない |

**チェックファイル:** `focus_not_obscured_enhanced.py`

#### フローチャート
```mermaid
flowchart TD
    TAB["Tabキー巡回ループ"] --> RATIO{"隠れている比率は？"}
    RATIO -- "10%以上" --> FAIL["不合格: 2.4.12 意味のある重なりが発生"]
    RATIO -- "2%から10%" --> REV["要確認: 軽微な重なり"]
    RATIO -- "2%未満" --> PASS["合格 (PASS)"]
```

#### 対象ケース
- 独自に作成されたオーバーレイに対する、より厳格な閾値。
- 2.4.11 と同様のキーボード巡回と重なり要素特定。

#### 未対応ケース
- 2% 未満の重なりであっても、非常に小さなフォーカス・コントロール等では影響が出る可能性。

### 3.3.2 — ラベル又は指示 (レベル A)
**チェックファイル:** `form_auditor.py`

#### フローチャート
```mermaid
flowchart TD
    INP["フォーム入力"] --> NAME{"アクセシブルな名前は？"}
    NAME -- なし --> FAIL1["不合格: 3.3.2 ラベルがない"]
    NAME -- あり --> REQ{"必須マーカーは？"}
    REQ -- "視覚的のみでARIAなし" --> FAIL2["不合格: 3.3.2 必須状態が定義されていない"]
    REQ -- OK --> AUTO{"Autocompleteの設定は？"}
    AUTO -- いいえ --> FAIL3["不合格: 3.3.2 個人データには autocomplete が必要"]

```

#### 対象ケース
- ラベルの関連付け (`<label for>`, `aria-label`)。

- プレイスホルダーのみのラベル。
- 個人データフィールドにおける `autocomplete` 属性。

#### 未対応ケース
- 入力に関する詳細な指示 (例: 日付形式など)。
