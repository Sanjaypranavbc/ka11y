## Auditor output record (common keys)

Every auditor returns a list of dicts. Each dict extends the crawler input with:

| Key | Type | Description |
|-----|------|-------------|
| `wcag_X_X_X_status` | `"FAILED"` \| `"PASSED"` \| `"N/A"` | Audit result |
| `wcag_X_X_X_violation` | str | Human-readable failure reason |
| `html_snippet` | str | Element HTML (from crawler) |
| `element_id` | str \| None | Element `id` attribute |
| `tag` | str | Element tag name |

## Finding (flat output shape)

Returned in `result.violations`, `result.needs_review`, and `result.passes`:

```typescript
interface Finding {
  source:         "axe" | "python" | "custom";
  rule_id:        string;           // e.g. "python_1_1_1_alt"
  wcag_sc:        string;           // e.g. "1.1.1"
  criterion_name: string | null;    // localized name
  level:          "A" | "AA" | "AAA" | null;     // stable machine value
  level_label:    string | null;    // localized companion (e.g. "レベル AA")
  severity:       "critical" | "high" | "medium" | "low" | null;  // stable machine value
  severity_label: string | null;    // localized companion (e.g. "重大")
  status:         "fail" | "pass" | "needs_review";  // stable machine value
  status_label:   string;           // localized companion (e.g. "合格")
  reason:         string;           // localized text rendered from i18n/rules.yml
  reason_code:    string | null;    // stable opaque template key (e.g. "fail_missing_alt")
  suggested_fix:  string | null;    // null for passes
  help_url:       string | null;
  element:        {
    html:       string;             // first 600 chars of outer HTML
    element_id: string | null;
    target:     string[];           // selector chain
    tag:        string | null;
    page_url:   string;
  } | null;                         // null for passes
}
```

The stable machine fields (`severity`, `level`, `status`, `reason_code`,
`wcag_sc`) are identical across languages and safe to filter on. The
`*_label` companions and the localized `criterion_name` / `reason` /
`suggested_fix` fields are sourced entirely from `i18n/rules.yml` and the
`i18n/locales/<lang>.yml` overlays.

## CombinedReport

Persisted to `combined_report.json` and included in `result`:

```typescript
interface CombinedReport {
  url:          string;
  generated_at: string;      // ISO-8601
  lang:         string;      // active language ("en" | "ja" | "de" | ...)
  labels: {                  // localized display labels for the active language
    severities: Record<string, string>;  // e.g. { "critical": "重大", ... }
    levels:     Record<string, string>;  // e.g. { "AA": "レベル AA", ... }
    statuses:   Record<string, string>;  // e.g. { "pass": "合格", ... }
  };
  warnings:     string[];
  warning_details?: WarningSample[];
  summary: {
    total_findings:  number;
    violations:      number;
    needs_review:    number;
    passes:          number;
    by_severity:     { critical: number; high: number; medium: number; low: number };
    by_level:        Record<"A" | "AA" | "AAA", { violations: number; needs_review: number; passes: number }>;
    by_wcag_sc:      Record<string, { violations: number; needs_review: number; passes: number }>;
    by_source:       Record<"axe" | "python", { violations: number; needs_review: number; passes: number }>;
  };
  violations:      Finding[];
  needs_review:    Finding[];
  passes:          Finding[];
  image_audit_report: ImageAuditReport | null;
  contrast_report: ContrastReport | null;
}
```

## ContrastReport

Produced by the OCR + WCAG 1.4.3 contrast analysis pipeline. Attached to `CombinedReport.contrast_report` when `run_ocr: true` and images are found.

```typescript
interface ContrastReport {
  summary: {
    total_regions_analysed:  number;
    total_violations:        number;
    images_with_violations:  number;
    pass_rate_pct:           number;   // 0–100
  };
  table:  ContrastDetection[];
  images: ContrastImageDetail[];
}

interface ContrastImageDetail {
  filename:                  string;
  path:                      string;   // Absolute server-side filesystem path
  image_url:                 string;   // Injected by backend: /api/v1/combined/{job_id}/image?path=...
  contrast_violations_count: number;
  detections:                ContrastDetection[];
}

interface ContrastDetection {
  text:            string;
  contrast:        number;             // WCAG contrast ratio
  wcag_violations: string[];           // ["aa_normal"] | ["aa_normal", "aa_large"] | []
  compliance: {
    aa_normal:  boolean;
    aa_large:   boolean;
    aaa_normal?: boolean;
    aaa_large?:  boolean;
  };
  image_path:    string;
  bounding_box?: number[];             // [x, y, w, h] pixels
}
```

## Localization Notes

Every text-bearing field in a finding is universally localized from the shared `i18n/rules.yml` and `i18n/locales/<lang>.yml` overlays. This applies to both Node and Python and covers every emit path:

| Field | Source |
|-------|--------|
| `criterion_name` | `rules.<sc>.name` |
| `description` (rules catalogue) | `rules.<sc>.description` |
| `suggested_fix` | `rules.<sc>.suggested_fix` |
| `reason` | `reason_templates.<sc>.<reason_code>` (with `_generic` block as catch-all) |
| `severity_label` | `severities.<severity>` |
| `level_label` | `levels.<level>` |
| `status_label` | `statuses.<status>` |
| Top-level `labels` | full `severities` / `levels` / `statuses` maps |

The stable machine values (`severity`, `level`, `status`, `reason_code`, `wcag_sc`) are guaranteed identical across locales and are the safe key to filter on.

axe-core ships its own per-locale messages and is configured via `axe.configure({ locale })` before each run, so axe-derived `reason` strings are localized natively by the engine.

Python emits a `reason_code` (e.g. `fail_missing_alt`, `capture_failed`, `needs_review_warning`) plus optional `reason_params`; the `_make_finding` factory resolves these through `i18n.loader.render_reason()`, which falls back to the shared `_generic` templates when an SC has no rule-specific template for the code.

Node emits localized reasons through `renderRuleReason()` for axe and through `renderReasonTemplate()` / `_t()` helpers in custom checks. Both share the same YAML source as Python.
