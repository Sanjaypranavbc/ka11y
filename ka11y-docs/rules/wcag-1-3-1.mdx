## What it checks

WCAG 1.3.1 requires that information, structure, and relationships conveyed through presentation can be programmatically determined or are available in text. This ensures that users of assistive technologies (like screen readers) receive the same structural information as sighted users.

ka11y's Python engine focuses on several key areas that go beyond basic linting:

1.  **Form Structure**: Validates that `<label>` elements are correctly associated with their inputs (via `for` attributes or wrapping).
2.  **Fieldsets and Legends**: Checks for the presence of `<fieldset>` and `<legend>` to group related controls (like radio button groups or complex address forms).
3.  **ARIA Landmark Relationships**: Validates that ARIA roles (like `navigation`, `main`, `search`) and properties (like `aria-labelledby`, `aria-describedby`) are used correctly to establish relationships.
4.  **Data Tables**: (Partial) Validates that table headers (`<th>`) are correctly used and associated with data cells.

## How it works

The universal crawler extracts a rich `SemanticContext` for every element, which includes:
- `section_type`: Computed macro-context (e.g., `FORM_REGION`, `DATA_TABLE`).
- `ancestor_tags` / `ancestor_roles`: Full hierarchy traversal.
- `described_by_text`: Pre-resolved text from `aria-describedby` IDs.

The `FormAccessibilityAuditor` then uses this data to verify that every input has a discernible relationship to its label and any relevant group instructions.

## Multi-language Support

Relationships are often established via text labels. ka11y's Japanese support includes word-boundary-safe checks for common relationship indicators (e.g., "必須", "注記") and handles CJK-specific form patterns.

## Common violations

| Violation | Example |
|-----------|---------|
| Orphaned label | `<label>Name:</label> <input type="text">` (missing `for` attribute) |
| Missing fieldset | A group of radio buttons for "Shipping Method" without a wrapping `<fieldset>` and `<legend>`. |
| Placeholder-only | Using `placeholder="Search"` as the only way to identify an input. |
| Broken ARIA ref | `aria-describedby="msg-123"` where no element with `id="msg-123"` exists. |

## Suggested fix

Use semantic HTML elements and explicit ARIA relationships.

```html
<!-- FAILED -->
<div>
  <span>Username:</span>
  <input type="text" name="user">
</div>

<!-- PASSED (Explicit Label) -->
<div>
  <label for="user-field">Username:</label>
  <input type="text" id="user-field" name="user">
</div>

<!-- PASSED (Wrapping Label) -->
<label>
  Username:
  <input type="text" name="user">
</label>

<!-- PASSED (Grouped controls) -->
<fieldset>
  <legend>Choose a shipping method:</legend>
  <label><input type="radio" name="ship" value="std"> Standard</label>
  <label><input type="radio" name="ship" value="exp"> Express</label>
</fieldset>
```
