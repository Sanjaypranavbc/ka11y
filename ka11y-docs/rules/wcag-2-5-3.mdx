## What it checks

For interactive elements that have visible text, the **accessible name** (what a screen reader or speech-input tool reads) must **contain** that visible text.

## Why this matters

Speech-input users (Dragon NaturallySpeaking, Voice Control) activate elements by speaking what they see. If the accessible name differs from the visible label, the command won't work.

**Example:**
```html
<!-- Visible text: "Submit form" -->
<!-- aria-label: "Send" -->
<button aria-label="Send">Submit form</button>
```
A user says "Click Submit form" — Dragon sends a click to the button. But the button's accessible name is "Send", so the user has to know to say "Click Send" — information not visible on screen.

## Computed accessible name

The auditor uses the `accessible_name` computed by `InteractiveElementCrawler`, which follows a simplified AccName 1.1 priority:

1. `aria-labelledby` (resolved text)
2. `aria-label`
3. `value` (submit/button inputs)
4. `alt` (image inputs)
5. Element text content
6. `title`

## Check logic

Both `visible_label` and `accessible_name` are normalised before comparison using `_normalize()`: Unicode NFC normalisation → `casefold()` → collapse whitespace. This correctly handles Unicode equivalences (e.g. `"Café"` vs `"Cafe\u0301"`).

The match uses a **word-boundary regex** (`\b...\b`) so that a visible label of `"Go"` does not match `"Gorilla"`.

| Condition | Status |
|-----------|--------|
| `visible_label` is empty or contains no word characters (icon-only) | `N/A` — rule does not apply |
| `accessible_name` is empty | `FAILED` — no accessible name at all |
| normalised `accessible_name` does not contain normalised `visible_label` at a word boundary | `FAILED` |
| normalised `accessible_name` contains normalised `visible_label` at a word boundary | `PASSED` |

## Elements audited

- `<button>` with visible text
- `<a>` with visible text
- `<input type="submit|button|reset|image">` with visible label
- Elements with ARIA interactive roles: `button`, `link`, `menuitem`, `tab`, `option`, `treeitem`, `gridcell`

Columns: `page_url`, `element_index`, `tag`, `role`, `element_id`, `input_type`, `visible_label`, `aria_label`, `aria_labelledby`, `aria_labelledby_text`, `title_attr`, `value_attr`, `alt_attr`, `accessible_name`, `wcag_2_5_3_status`, `wcag_2_5_3_violation`, `overall_status`, `html_snippet`

## Common violations

| Violation | Visible label | Accessible name |
|-----------|--------------|-----------------|
| Synonym substitution | "Buy now" | "Purchase" |
| Abbreviation | "Search" | "Srch" |
| Language mismatch | "Submit" | "Soumettre" |
| Extra prefix only | "Submit" | "Form Submit" — passes (contains "Submit") |
| Icon + tooltip | *(empty)* | "Close" — N/A (no visible label) |

## Suggested fix

```html
<!-- Bad: aria-label replaces the visible text -->
<button aria-label="Send form">Submit</button>

<!-- Good: aria-label contains the visible text -->
<button aria-label="Submit the contact form">Submit</button>

<!-- Good: no aria-label needed when visible text is sufficient -->
<button>Submit</button>

<!-- Good: aria-labelledby pointing to visible text -->
<span id="btn-label">Submit</span>
<button aria-labelledby="btn-label extra-context">Submit</button>
```

## Known limitations

- **Icon-only controls** with no visible label cannot be flagged (WCAG-correct, but a badly named icon escapes detection).
- **Shadow DOM** is not traversed — controls inside closed shadow roots are not audited.
- **Punctuation normalisation** — visible "Sign up!" vs accessible "Sign up" passes substring even though the token differs.
