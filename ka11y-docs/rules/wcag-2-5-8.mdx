<Info>
  **Level AA** · WCAG 2.2 · **Primary Engine:** Unified Pipeline (`Policy258`) · **Secondary Engine:** `TargetSizeAuditor` (Python Static)
</Info>

## What it checks

Every interactive element must have a **rendered size** of at least **24 × 24 CSS pixels**, or must have sufficient spacing around it so that the 24 × 24 target area does not overlap with another target.

## How it works (Unified Pipeline)

The Unified Pipeline performs a more sophisticated analysis of clickable areas than standard static checkers:

1.  **Effective Clickable Area Calculation**: `ElementContextExtractor` merges the bounding box of small native inputs (like a 12x12px radio button) with their wrapping `<label>` or `<button>` padding.
2.  **Spatial Indexing**: The engine uses a Chebyshev distance algorithm (O(N²)) inside the browser to calculate the exact pixel distance to the nearest adjacent interactive element.
3.  **Policy Evaluation**: `Policy258` applies the 24x24 rule and its exceptions based on this merged geometry.

### False Positive Protection

*   **Label Merging**: A classic false positive is a tiny native input that is part of a large, easy-to-tap label. The pipeline correctly identifies this as a single **Effective Clickable Area** and evaluates the merged box, which usually passes the rule.
*   **Dynamic Spacing Exceptions**: WCAG 2.5.8 exception 5 allows for undersized targets if they have sufficient surrounding spacing. The pipeline's spatial index proves exactly how far apart nodes are, correctly applying this exception.
*   **UA-Controlled Detection**: The engine accurately detects native inputs where CSS `appearance` has not been overridden, correctly applying the User-Agent exception (Exception 4).

## Measured dimensions

The crawler uses `getBoundingClientRect()` via Playwright to get the **actual rendered dimensions** — not the CSS `width`/`height` properties. This correctly handles:
- Elements whose size is determined by padding or content
- Elements whose dimensions are set in relative units (em, %, vw)
- Elements inside a responsive grid that collapse below their specified size

## Exceptions (N/A cases)

WCAG 2.5.8 provides several exceptions. ka11y automatically detects three:

| Exception | Condition | Detection |
|-----------|-----------|-----------|
| **Inline** | `<a>` within a sentence of text | `getComputedStyle().display === 'inline'` |
| **UA-controlled** | Native checkbox / radio without custom styling | `getComputedStyle().appearance` is `auto`, `checkbox`, or `radio` |
| **Offset** | Target is below 24×24 but has enough surrounding spacing | Inflate target by required offsets `((24-w)/2, (24-h)/2)` and verify no other target intersects that inflated box |

Elements matching an exception are reported as `N/A` and excluded from the violation count.

## Output

**CSV file:** `audit_target_size_report.csv`

Columns: `page_url`, `element_index`, `tag`, `role`, `element_id`, `input_type`, `accessible_name`, `rendered_width_px`, `rendered_height_px`, `padding_top_px`, `padding_bottom_px`, `padding_left_px`, `padding_right_px`, `is_inline_exception`, `is_ua_controlled_exception`, `is_offset_exception`, `required_offset_x_px`, `required_offset_y_px`, `nearest_target_gap_x_px`, `nearest_target_gap_y_px`, `passes_size`, `wcag_2_5_8_status`, `wcag_2_5_8_violation`, `overall_status`, `html_snippet`

A summary row (`── SUMMARY ──`) is appended at the end of the CSV.

### `summarize()` return keys

| Key | Description |
|-----|-------------|
| `total_elements` | All elements audited |
| `checked` | Elements where rule applied (PASSED + FAILED, excludes N/A) |
| `passed` | Elements ≥ 24×24 px |
| `failed` | Elements < 24×24 px |
| `na` | Elements matching an exception |
| `pass_rate_pct` | `passed / checked × 100`, rounded to 1 dp |
| `wcag_2_5_8_failed` | Same as `failed` |
| `failed_by_tag` | `dict[tag, count]` — e.g. `{"A": 3, "BUTTON": 1}` |

## Common violations

| Element | Typical issue |
|---------|--------------|
| Small icon links | `<a>` with only a 16 × 16 icon, no padding |
| Compact nav items | `<li><a>` items in a tight toolbar |
| Social share buttons | `<a>` wrapped around 14 × 14 SVG icon |
| Small pagination links | `<a>` with `padding: 2px 4px` |

## Suggested fix

```css
/* Increase the click/touch area without changing visual size */
.icon-link {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  min-width: 24px;
  min-height: 24px;
  padding: 4px;   /* adds to clickable area */
}

/* Or use the newer CSS approach */
.icon-link {
  min-width: 24px;
  min-height: 24px;
}
```

For elements where you cannot change the visual size:

```css
/* Use a transparent pseudo-element to extend the tap target */
.small-button {
  position: relative;
}
.small-button::after {
  content: "";
  position: absolute;
  top: 50%; left: 50%;
  transform: translate(-50%, -50%);
  min-width: 24px;
  min-height: 24px;
}
```

## Known limitations

- **Viewport-coupled** — measurements run at 1440 px viewport. Mobile-specific sizing issues (often more severe) are not captured without reconfiguring the crawler.
- **Iframe contents** are not traversed.
- **Essential / equivalent exceptions** require human judgment and are not auto-applied.
- **Z-index stacking** — transparent overlaid targets can trigger false offset-intersection failures.
