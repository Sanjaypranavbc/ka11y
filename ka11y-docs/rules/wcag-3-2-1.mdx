## What it checks

WCAG 3.2.1 requires that when any user interface component receives focus, it does not result in a change of context. A "change of context" includes major changes in the content of the Web page that, if made without user awareness, can disorient users (e.g., opening a new window, moving focus to a different component, or navigating to a new page).

## How it works

The Node engine performs an interactive audit by monitoring page state during focus traversal:

1.  **Event Hooking**: Injects hooks into `history.pushState`, `history.replaceState`, and monitors the `framenavigated` event.
2.  **Focus Simulation**: For each focusable element, the engine triggers a `.focus()` action and waits 100ms.
3.  **Context Monitoring**:
    *   **Navigation Detection**: Detects if the URL pathname or query parameters change.
    *   **Skip-Link Exemption**: Correctly recognizes and exempts internal fragment changes (e.g., `#main-content`) commonly used by skip links.
    *   **SPA Route Changes**: Intercepts soft-navigation in Single Page Applications.

## Status Semantics

*   **FAIL**: Focusing an element results in a non-fragment URL change or major context shift.
*   **PASS**: The page state remains stable during focus simulation.

## Common violations

| Violation | Example |
|-----------|---------|
| Auto-navigation | A nav menu where focusing an item automatically navigates to that page without clicking. |
| Automatic popups | A button that opens a new window or modal as soon as it is reached via Tab. |

## Suggested fix

Ensure that focus actions are purely navigational within the current context. All significant changes should be triggered by an explicit `click` or `Enter` key event.

```javascript
// FAILED - Auto-navigation on focus
const menuLink = document.querySelector('.auto-nav');
menuLink.addEventListener('focus', () => {
  window.location.href = menuLink.href;
});

// PASSED - Navigation only on click
menuLink.addEventListener('click', (e) => {
  // standard browser behavior
});
```

## Known limitations

*   **Modal Overlays**: Opening a visual modal that does not change the URL or significantly alter the DOM structure may not be flagged as a context change.
*   **JavaScript-Only Changes**: Route changes that do not use the History API or change the URL may evade detection.
