## What it checks

WCAG 1.4.5 requires that if the technologies being used can achieve the visual presentation, text is used to convey information rather than an image of text.

ka11y uses a multi-layered approach to detect images that contain significant text, distinguishing them from exempt categories like logos.

## How it works

### Unified Pipeline (`Policy145`)
The pipeline evaluates images by combining structural context with OCR data:
1.  **OCR Detection**: PaddleOCR/EasyOCR extracts text from images.
2.  **Classification Filtering**: The policy automatically bypasses elements classified as `logo`, `decorative`, `complex`, or `chart`, as these are typically exempt from the rule.
3.  **Contextual Awareness**: Exempts video posters/thumbnails (`video_context`) that might have burned-in titles.
4.  **Verdict Generation**: If significant text is detected in a non-exempt image, it triggers a violation.

### Node Engine (`images-of-text.check.js`)
The Node engine performs a heuristic preflight using:
*   **Filename Scoping**: Checks `src` paths for keywords like "banner", "heading", "title", "text".
*   **Attribute Analysis**: Evaluates long or sentence-like `alt` text as a signal.
*   **CSS Backgrounds**: Supplemental check flags CSS `background-image` URLs that contain text-indicating keywords.

## False Positive Protection

*   **Dynamic Reasons**: The violation message includes a snippet of the exact text detected by OCR, allowing for immediate human verification.
*   **Exact-Match Downgrading**: If the `alt` text exactly matches the OCR-detected text and the image is small, it may be downgraded to **PASSED** if the presentation is considered essential.
*   **Logo Recognition**: Robust keyword matching for brands and logos prevents false failures on corporate branding.

## Common violations

| Violation | Example |
|-----------|---------|
| Styled heading image | A `<h1>` replaced by an `<img>` of stylized text. |
| Text in hero banner | A large hero image with promotional text baked into the pixels instead of using CSS overlays. |
| CSS background text | A call-to-action button where the text is part of a background image. |

## Suggested fix

Use CSS and web fonts to achieve visual styling instead of baking text into images.

```html
<!-- FAILED -->
<img src="/assets/hero-text.png" alt="Summer Sale 50% Off">

<!-- PASSED -->
<div class="hero-container">
  <img src="/assets/hero-bg.jpg" alt=""> <!-- decorative background -->
  <div class="hero-overlay">
    <h1>Summer Sale</h1>
    <p>50% Off</p>
  </div>
</div>

<style>
.hero-overlay h1 {
  font-family: 'Brand Font', sans-serif;
  font-size: 3rem;
  color: #ff0000;
  text-shadow: 2px 2px #000;
}
</style>
```

## Known limitations

*   **Essential Presentation**: The auditor cannot always determine if a particular visual presentation is "essential" (e.g., a specific typographic art piece).
*   **Heuristic Dependency**: Node-side checks rely on filename and attribute patterns and may miss images with neutral names like `image_1.png`.
