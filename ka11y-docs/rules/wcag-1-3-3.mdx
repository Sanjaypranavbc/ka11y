## What it checks

WCAG 1.3.3 requires that instructions for understanding and operating content do not rely solely on sensory characteristics such as shape, color, size, visual location, orientation, or sound. 

ka11y uses an advanced NLP-backed auditor to identify instructional sentences and determine if they contain "sensory-only" references without a corresponding non-sensory identifier.

## How it works

The `SensoryCharacteristicsAuditor` follows a multi-stage pipeline:

1.  **Instruction Detection**: Identifies imperative commands or declarative guidance.
2.  **Sensory Word Extraction**: Searches for words belonging to 8 sensory categories (Color, Shape, Size, Position, Orientation, Sound, Brightness, Texture).
3.  **Meaningful Label Check**: Strips sensory words and generic UI nouns. If unique identifiers or quoted strings remain, it passes.

## Multi-language & Japanese Support

The auditor has been significantly hardened for Japanese-language auditing:

*   **Large Model Preference**: Prefers `ja_core_news_lg` (94%+ POS accuracy) over smaller models for better web-register text analysis.
*   **SudachiPy Morpheme Filtering**: Uses SudachiPy for tokenization and morpheme-level stop-word filtering. This prevents Japanese particles (は, が, を) from surviving as phantom "content" words.
*   **NFKC Normalization**: Automatically normalizes half-width katakana (`ｶﾀｶﾅ` → `カタカナ`) and full-width alphanumeric characters before processing to ensure consistent pattern matching.
*   **Expanded Taxonomy**: Includes a comprehensive Japanese sensory word taxonomy (e.g., 赤, 青, 丸, 四角, 右, 左).

| Feature | English Implementation | Japanese Implementation |
|---------|------------------------|-------------------------|
| **NLP Engine** | `en_core_web_sm` | `ja_core_news_lg` (preferred) |
| **Sentence Splitting** | Regex `[.!?]` | Regex `[。！？]` |
| **Quotation Marks** | `" "`, `“ ”`, `‘ ’` | `「 」`, `『 』` |
| **Taxonomy** | Standard EN sensory words | Full Japanese sensory word taxonomy |

## Output

**CSV file:** `audit_sensory_report.csv`

Columns: `page_url`, `element_tag`, `element_id`, `sentence`, `sensory_categories`, `wcag_1_3_3_status`, `wcag_1_3_3_violation`, `overall_status`, `selector`, `element_ref_id`, `frame_path`, `html_snippet`

Status values: `PASSED` · `FAILED`

## Common violations

| Violation | Example |
|-----------|---------|
| Color only | "Click the **red** button to continue." |
| Shape only | "Select the **square** icon." |
| Position only | "Refer to the instructions on the **right**." |
| Sound only | "Wait for the **beep** before typing." |

## Suggested fix

Always pair sensory characteristics with a text label or a unique non-sensory identifier.

```html
<!-- FAILED -->
<p>Required fields are marked in red.</p>

<!-- PASSED -->
<p>Required fields are marked in red and indicated with an asterisk (*).</p>

<!-- FAILED -->
<button class="round-btn">○</button>
<p>Click the round button.</p>

<!-- PASSED -->
<button class="round-btn" aria-label="Submit">○</button>
<p>Click the round "Submit" button.</p>
```

## Known limitations

- **Vocabulary exhaustion** — `SENSORY_WORDS` is a finite list; novel sensory adjectives ("translucent", "neon") escape detection.
- **Japanese (CJK)** — word-boundary detection uses a content-character fallback; leftover structural tokens can yield false passes.
- **Semantic disconnect** — validates instruction *phrasing* only, not whether the real button has a visible non-sensory label.
