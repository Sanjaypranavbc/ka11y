## Node custom checks

`ka11y-node` ships **24** custom checks alongside axe-core. They run inside the same `axe_core` stage and cover criteria that need extra DOM heuristics or live interaction.

| Mode | Count | Examples | Notes |
|------|-------|----------|-------|
| **Static** | 19 | `1.2.1`, `1.4.1`, `2.4.5`, `3.3.8`, `4.1.3` | DOM heuristics, metadata checks, and single-page signals. Ambiguous evidence is intentionally returned as `incomplete`. |
| **Interactive** | 5 | `2.1.2`, `2.4.7`, `2.4.13`, `3.2.1`, `3.2.2` | Focus, keyboard, and input mutations executed sequentially against the loaded page. |

Important conservative behaviors in the current implementation:

- `1.2.1` does not treat `<track>` by itself as enough for an audio-only transcript.
- `3.1.6` pronunciation heuristics no longer auto-fail ruby-free CJK pages; they stay `incomplete` unless the criterion is clearly not applicable.
- `3.2.6` consistent-help remains `incomplete` from a single-page audit because cross-page consistency cannot be proven statically.
- `2.4.8` only passes on visible current-location cues. Sitemap and JSON-LD hints alone stay `incomplete`.
- `4.1.3` no longer fails a page just because forms exist without live regions.
- SC-filtered Node requests now short-circuit custom-check execution: when `/analyze-accessibility` or `/analyse-url` is called with `successCriteriaId`, only custom checks mapped to that criterion are executed.

See [Node Custom Checks](/rules/node-custom-checks) for the full rule-by-rule catalogue.

## Two audit engines

### Static auditors
Use Playwright to extract DOM data, then apply rule logic in Python without re-rendering. Fast, deterministic, good for structural checks (alt text, form labels, target sizes).

### Rendered-layout engine
Simulates real browser scenarios and captures layout snapshots at each state. Used for rules that depend on visual rendering — text resize, viewport reflow, spacing overrides, orientation, hover popups, and focus visibility.

| Scenario | Viewport | What changes |
|----------|----------|-------------|
| `baseline` | 1280 × 720 | Normal desktop |
| `resize_text_200` | 1280 × 720 | `font-size: 200%` on `<html>` |
| `reflow_320` | 320 × 640 | Narrow mobile viewport |
| `text_spacing_override` | 1280 × 720 | WCAG 1.4.12 CSS overrides |
| `orientation_portrait` | 390 × 844 | Portrait mobile |
| `orientation_landscape` | 844 × 390 | Landscape mobile |
| `focus_scan` | 1280 × 720 | Tab traversal (up to 100 steps) |
| `hover_scan` | 1280 × 720 | Hover/focus candidate triggers |

<Tip>
  WCAG **1.4.3** is a special case: axe-core checks DOM text contrast but has no visibility into text rendered inside images. ka11y's OCR pipeline fills this gap — see [1.4.3 Contrast (Minimum)](/rules/wcag-1-4-3) for the full pipeline description.
</Tip>
