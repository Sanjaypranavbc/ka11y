## Severity mapping

Python auditors map each WCAG SC to a default severity level:

| WCAG SC | Severity |
|---------|---------|
| 1.1.1 | `critical` |
| 1.4.3 | `high` |
| 2.2.2 | `high` |
| 2.5.3 | `high` |
| 2.5.8 | `medium` |
| 3.3.1 | `high` |
| 3.3.2 | `high` |

axe-core assigns its own severity values (`critical`, `serious`, `moderate`, `minor`) which are mapped to the ka11y schema (`critical`, `high`, `medium`, `low`) in `axeResultMapper.js`.

## Why Python auditors go beyond axe-core

axe-core performs static DOM analysis. It cannot:
- **Read image content** — only checks that `alt` is present, not whether it's accurate
- **Detect CSS animations** — only flags deprecated `<blink>` and `<marquee>`
- **Measure rendered dimensions accurately** for all elements (2.5.8 support is absent)
- **Verify speech-input usability** across all ARIA roles (2.5.3)
- **Check autocomplete requirements** for personal-data fields (3.3.2)

The Python auditors complement axe-core in exactly these areas.

<Tip>
  WCAG **1.4.3** is a special case: axe-core checks DOM text contrast but has no visibility into text rendered inside images. ka11y's OCR pipeline fills this gap — see [1.4.3 Contrast (Minimum)](/rules/wcag-1-4-3) for the full pipeline description.
</Tip>
