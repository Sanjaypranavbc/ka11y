## Language support

ka11y targets **English and Japanese** as primary audit languages. Finding text (criterion names, reasons, suggested fixes) is fully localised via the shared `i18n/rules.yml` + locale overlay system.

NLP-backed rule quality differs between languages:

| Rule category | EN | JA |
|---|---|---|
| NLP text analysis (1.3.3, 2.4.9, 3.3.3) | Strong | Partial |
| Keyword pattern matching (Node checks) | Strong | Partial |
| OCR-based image checks | Strong | Partial |
| DOM-structural checks (contrast, forms, ARIA) | Strong | Strong |
| Rendered layout checks | Strong | Strong |

Japanese audits produce valid findings but with a higher false-positive/false-negative rate in NLP-dependent rules. The 2026-04-24 sprint upgraded the Japanese spaCy pipeline to prefer `ja_core_news_lg` (94%+ POS accuracy) and added SudachiPy morpheme-level POS filtering in the sensory auditor — both with graceful fallbacks if the optional packages are not installed. Install `poetry install -E japanese` + `python -m spacy download ja_core_news_lg` to activate.

See [WCAG Technique Coverage Matrix — Language Support](/rules/coverage-matrix#language-support-limitations) and [Japanese Language Support](/internals/japanese-language-support) for the full gap analysis and recommended fixes.

## Two audit engines

### Static auditors
Use Playwright to extract DOM data, then apply rule logic in Python without re-rendering. Fast, deterministic, good for structural checks (alt text, form labels, target sizes).

### Rendered-layout engine
Simulates real browser scenarios and captures layout snapshots at each state. Used for rules that depend on visual rendering — text resize, viewport reflow, spacing overrides, orientation, hover popups, and focus visibility.

| Scenario | Viewport | What changes |
|----------|----------|-------------|
| `baseline` | 1280 × 720 | Normal desktop |
| `resize_text_200` | 1280 × 720 | `font-size: 200%` on `<html>` |
| `reflow_320` | 320 × 640 | Narrow mobile viewport |
| `text_spacing_override` | 1280 × 720 | WCAG 1.4.12 CSS overrides |
| `orientation_portrait` | 390 × 844 | Portrait mobile |
| `orientation_landscape` | 844 × 390 | Landscape mobile |
| `focus_scan` | 1280 × 720 | Tab traversal (up to 100 steps) |
| `hover_scan` | 1280 × 720 | Hover/focus candidate triggers |

<Tip>
  WCAG **1.4.3** is a special case: axe-core checks DOM text contrast but has no visibility into text rendered inside images. ka11y's OCR pipeline fills this gap — see [1.4.3 Contrast (Minimum)](/rules/wcag-1-4-3) for the full pipeline description.
</Tip>
