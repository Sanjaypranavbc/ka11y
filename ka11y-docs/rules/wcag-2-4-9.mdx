</Info>

## What it checks

WCAG 2.4.9 requires that the purpose of each link can be identified from the link text alone, except where the purpose of the link would be ambiguous to users in general. This is a stricter version of 2.4.4 (which allows context).

ka11y flags generic link text like "click here" or "read more" that provides no information about the destination.

## How it works

The Node engine analyzes a sample of up to 100 links per page:

1.  **Accessible Name Resolution**: It resolves the accessible name of each link using the standard priority: `aria-label` → `aria-labelledby` → `img[alt]` inside the link → visible text.
2.  **Generic Pattern Matching**: The resolved name is checked against a database of generic/ambiguous phrases in multiple languages.

### Multilingual Patterns

| Language | Generic Phrases |
|----------|-----------------|
| **English** | click here, read more, details, more, learn more, info, here, download |
| **Japanese** | こちら, 詳細, もっと見る, 続きを読む, ここをクリック, 詳しくはこちら, 続きはこちら, もっと詳しく, ご覧ください, お読みください |

## Status Semantics

*   **FAIL**: The link's accessible name consists solely of a generic/ambiguous phrase.
*   **PASS**: The link's accessible name is unique or descriptive.

## Common violations

| Violation | Example |
|-----------|---------|
| Generic text | `<a href="/report.pdf">Click here</a>` |
| Ambiguous "More" | Multiple "Read more" links on a blog homepage with no unique labels. |
| ARIA misuse | `<a href="/profile" aria-label="Details">My Profile</a>` (The `aria-label` makes it ambiguous). |

## Suggested fix

Use descriptive link text that identifies the destination or purpose.

```html
<!-- FAILED -->
<a href="/annual-report-2025.pdf">Click here</a>

<!-- PASSED -->
<a href="/annual-report-2025.pdf">Download Annual Report 2025 (PDF)</a>

<!-- PASSED (using aria-label for visual design) -->
<a href="/news/123" aria-label="Read more about our new solar initiative">
  Read more
</a>
```

## Known limitations

*   **Ambiguity Exception**: Some links are naturally ambiguous to all users; the auditor cannot auto-exempt these.
*   **Icon-only Links**: Links that contain only an SVG or icon without a text alternative are handled by other rules (e.g., 1.1.1, 4.1.2) but may still trigger a 2.4.9 failure if their name resolves to something generic.
*   **Shadow DOM**: Links inside shadow roots are currently not traversed by this check.
