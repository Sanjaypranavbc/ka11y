## What it checks

Any interactive widget that requires a **multipoint gesture** (e.g. two-finger pinch/zoom) or a **path-based gesture** (e.g. swipe, drag along a specific path) must also offer an equivalent interaction achievable with a **single pointer** (one tap, one click, one keypress).

The audit runs three complementary layers:

| Layer | How it works |
|---|---|
| `dom-pattern` | CSS selector bank matches carousel, drag-and-drop, map embed, touch widget, and path-based interaction elements in the live DOM. |
| `library-detected` | JavaScript global variable scan and script `src` fingerprinting identify gesture libraries (Hammer.js, Swiper, Interact.js, etc.) even when no matching DOM element is found. |
| `axe-rule` | Custom axe-core rule checks gesture data-attributes (`data-swipe`, `data-pinch`, `draggable="true"`, and Japanese equivalents) for missing single-pointer alternatives inline. |

## Why this matters

Users with limited hand dexterity, motor impairments, or switch-access devices often cannot perform multi-touch or precise-path gestures.  Without a single-pointer alternative they are completely excluded from the functionality.

## Escape hatch detection

After flagging a candidate element the auditor checks whether an **escape hatch** (single-pointer alternative) already exists:

| Check | Evidence string example |
|---|---|
| `onclick` / `onclick=""` attribute | "Click handler present on element" |
| `onkeydown` / `onkeypress` on element or ancestor | "Keyboard handler (onkeydown) on element" |
| `aria-controls` or `aria-haspopup` | "aria-controls=\"panel-id\" present" |
| `<button>` / `[role="button"]` child | "Child \<button\> provides a pointer alternative" |
| `<button>` / `[role="button"]` sibling | "Sibling \<button\> found in parent" |
| `tabIndex >= 0` on element or sibling | "Element is tab-focusable (tabIndex >= 0)" |

Findings where an escape hatch is detected are downgraded to **warning** for manual review.  Findings with no escape hatch are emitted as **violation**.

## Multilingual support

The selector bank merges English and Japanese selectors when `<html lang="ja">` or `lang="ja-JP"` is detected.

Japanese-specific selectors include:
- CSS class names: `.スライダー`, `.カルーセル`, `.ドラッグ`, `.並び替え`
- Data attributes: `[data-スワイプ]`, `[data-タッチ]`, `[data-ジェスチャー]`, `[data-フリック]`
- Map providers: `iframe[src*="map.yahoo.co.jp"]`, `iframe[src*="zenrin.co.jp"]`, `iframe[src*="mapion.co.jp"]`

## Output structure

`auditPointerGestures()` returns:

```js
{
  pageUrl: string,
  pageLang: string,
  gestureLibrariesDetected: string[],   // e.g. ["swiper", "hammer.js"]
  domFindingsCount: number,
  violations: ViolationRecord[],         // severity: "violation"
  warnings:   ViolationRecord[],         // severity: "warning"
  summary: {
    total: number,
    violations: number,
    warnings: number,
    layers: { domPattern, libraryDetected, axeRule }
  }
}
```

Each `ViolationRecord` contains:

| Field | Type | Description |
|---|---|---|
| `ruleId` | `string` | `"wcag-2.5.1-pointer-gestures"` |
| `wcag` | `string` | `"2.5.1"` |
| `wcagLevel` | `string` | `"AA"` |
| `impact` | `string` | `"serious"` |
| `layer` | `string` | `"dom-pattern"`, `"library-detected"`, or `"axe-rule"` |
| `category` | `string` | Selector bank category (e.g. `"carousels"`) |
| `element` | `string\|null` | outerHTML excerpt (≤ 300 chars) |
| `selector` | `string` | Computed CSS path |
| `boundingBox` | `Object\|null` | `{ x, y, width, height }` from Playwright |
| `escapeHatchFound` | `boolean` | Whether a single-pointer alternative was detected |
| `escapeHatchEvidence` | `string[]` | Description of each detected alternative |
| `gestureLibrariesDetected` | `string[]` | Libraries identified on the page |
| `severity` | `"violation"\|"warning"` | `"warning"` if escape hatch found |
| `helpUrl` | `string` | W3C Understanding page |
| `timestamp` | `string` | ISO 8601 |

## Usage

```js
import { auditPointerGestures } from './audits/wcag-2.5.1/index.js';
import { adaptToReportFormat }  from './reporters/wcag-251-report-adapter.js';

// Inside your per-page crawler handler:
const result = await auditPointerGestures(page, {
  pageUrl,
  runAxeRule: true,
  axeScriptPath: 'node_modules/axe-core/axe.min.js',  // default
});

const reportItems = adaptToReportFormat(result);
// Feed reportItems into your existing report builder
```

## Known limitations

- **Inline gesture logic** wired via `addEventListener` directly in bundled JS (React, Vue, Angular) is **not visible** to the DOM selector layer or the axe rule; Layer 2 (`gesture-listener-detector.js` — the existing monkey-patch layer) must be injected **before** navigation to capture these.
- **Map embeds** are flagged as candidates but whether the map actually requires gestures (vs offering keyboard zoom controls) cannot be determined without interaction simulation.
- **Essential gestures** (e.g. a drawing app's brush stroke) cannot be auto-exempted; these findings require manual triage.
- **Cross-origin iframes** are not inspected — third-party widget gesture requirements remain invisible.
- The axe-core layer fires only on attribute-bearing elements; gesture logic in event listeners bypasses it.
