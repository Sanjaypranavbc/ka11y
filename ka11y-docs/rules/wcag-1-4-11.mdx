## What it checks

WCAG 1.4.11 requires that the visual presentation of graphical objects and user interface components have a contrast ratio of at least **3:1** against adjacent color(s).

ka11y audits this specifically for:
1.  **UI Components**: Functional images (buttons, icons in links) that serve as interactive controls.
2.  **Graphical Objects**: Informative icons or parts of graphics required to understand the content.

## How it works

The auditor leverages the same OCR and color-sampling pipeline as [1.4.3 Contrast (Minimum)](/rules/wcag-1-4-3), but applies the 3:1 threshold to non-text elements:

1.  **Component Detection**: Identifies images classified as `functional/icons`, `functional/buttons`, or `informative/icons`.
2.  **Luminance Analysis**: Samples the dominant foreground colors of the graphic and the background colors of the adjacent area.
3.  **Ratio Calculation**: Computes the contrast ratio. If the ratio is below 3:1, it is flagged as a violation.

## Output

**CSV file:** `audit_report.csv` (shared with 1.1.1)

Columns: `wcag_1_4_11_status`, `wcag_1_4_11_reason`

In the combined API, these findings appear with `wcag_sc: "1.4.11"`.

## Common violations

| Violation | Example |
|-----------|---------|
| Low-contrast icon | A light-blue "Search" icon on a white background (ratio < 3:1). |
| Faint border | A button with a very thin, light-grey border that is the only way to identify it as a button. |
| Decorative-only? | An icon that is intended to be informative but fails contrast, making it effectively invisible to low-vision users. |

## Suggested fix

Ensure that all meaningful graphical elements have a contrast ratio of at least 3:1.

```css
/* FAILED */
.icon-search {
  color: #cccccc; /* Light grey on white = 1.6:1 */
}

/* PASSED */
.icon-search {
  color: #767676; /* Mid grey on white = 4.5:1 (exceeds 3:1) */
}
```

If an icon is accompanied by a text label that already passes 1.4.3, the icon itself may be considered decorative and exempt from 1.4.11. However, ka11y recommends maintaining 3:1 contrast for all functional graphics for better usability.

## Known limitations

- **Fill-only buttons** (no border, background colour only) emit N/A because no UI boundary is detectable.
- **Active / hover / focus state contrast** is not measured — only the default rendered state.
- **Charts and data visualisations** exempt by G207 are not distinguished; decorative chart borders may be flagged.
