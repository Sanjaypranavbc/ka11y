## Current Production Path

As of `2026-04-13`, the combined audit pipeline does **not** launch seven static crawlers independently anymore.

- `AsyncImageCrawler` still owns image/OCR work.
- `RenderedLayoutCrawler` still owns viewport, focus, hover, reflow, resize-text, and rendered text-spacing scenarios.
- Static DOM rule families now share one browser load through `UniversalPageLoader` in `ka11y/crawler/universal_page.py`, then normalize back into the existing Pydantic models with `SnapshotNormalizer`.

That universal static path currently powers:

- forms
- interactive elements
- target size
- moving content
- media
- text spacing
- sensory characteristics

The important practical difference is that the combined pipeline now gets:

- same-origin iframe traversal with `frame_path` provenance
- open shadow-root traversal with composed selectors
- structured warnings for cross-origin frames and partial extraction
- sampled `warning_details` in the final `combined_report.json`
- stronger page-aware finding dedup across static and rendered paths
- config-driven budgets for OCR, hover scans, focus scans, and warning samples
- persisted `universal_snapshot_raw.json`, `universal_snapshot_normalized.json`, and Rich step logs
- `image_audit_report` image records even when OCR is disabled; `contrast_report` remains OCR-only

The legacy crawler classes still exist and keep the same model contracts, so direct usage and compatibility paths remain intact.

## Real-Page Testing Modes

There are now two documented real-site testing modes.

### 1. Focused universal-static matrix

**Plan file**: `ka11y-python/scripts/live_stage_plan.public_matrix.yml`

Use this when the goal is to validate the universal static crawler itself:

- iframe traversal
- shadow traversal
- loading-indicator exceptions
- Japanese routing through the combined pipeline
- normalized model coverage for forms, media, moving content, text spacing, target size, and sensory checks

This matrix intentionally disables some expensive rendered and OCR stages per site so failures can be isolated to the universal static path.

### 2. Full-stack matrix with all rules enabled

**Plan file**: `ka11y-python/scripts/live_stage_plan.public_full_stack.yml`

This is the production-style real-page suite. It leaves every `run_*` flag unset, so `CombinedRequest` defaults apply and all rule families remain enabled:

- axe-core / ka11y-node
- OCR + image audit
- forms
- label in name
- pause / stop / hide
- target size
- resize text
- reflow
- text spacing
- orientation
- hover / focus content
- focus not obscured minimum / enhanced
- sensory characteristics

Run it with:

```bash
python ka11y-python/scripts/live_stage_audit.py \
  --plan ka11y-python/scripts/live_stage_plan.public_full_stack.yml \
  --output-dir /tmp/ka11y_public_matrix_full \
  --node-base-url http://localhost:3000
```

### Reading the result

Each run produces:

- a plan summary markdown/json file
- per-run `combined_report.json`
- `universal_snapshot_raw.json`
- `universal_snapshot_normalized.json`
- `universal_snapshot_warnings.json`
- Rich step logs in `step_logs/`

`combined_report.json` now also carries `warning_details`, which is a sampled view of the universal crawler limitations that were recorded during extraction.

For image-heavy runs, remember the split contract:

- `image_audit_report` is populated when `run_image_audit=true`, even if `run_ocr=false`
- `contrast_report` is only populated when `run_ocr=true`
- frontend image viewers should accept image URLs from either report type

An expectation pass means:

- the page completed end-to-end
- the expected crawler coverage was observed on a real site
- the targeted architecture promise from `CRAWLER_ANALYSIS.md` held on that live page

## Runtime Config Knobs

These crawler controls now live in the shared repo-root `config/universal.yml` and are read through `ka11y/utils/crawler_settings.py` on the Python side and `sharedConfigLoader.js` on the Node side.

| Config key | Purpose |
|-----------|---------|
| `browser.ignore_https_errors` | Shared default for Playwright/Puppeteer TLS handling. This prevents expired or misconfigured target certificates from turning into generic frontend failures during normal crawls. |
| `crawler.language.cjk_langs` | Builds the rendered text-spacing override CSS for JA/ZH/KO-style languages |
| `crawler.reporting.max_warning_samples` | Caps how many warning samples are surfaced into `warning_details` |
| `crawler.performance.max_focus_steps` | Bounds rendered focus traversal |
| `crawler.performance.max_hover_candidates` | Bounds rendered hover probing candidates |
| `crawler.performance.max_ocr_images_per_run` | Caps OCR work on heavy pages and enables allowlist-based OCR selection |

Config loading is cached through `load_config()`, but callers receive defensive copies so helper usage stays mutation-safe.

### Navigation hardening for image crawl

`AsyncImageCrawler` now hardens real-site navigation before OCR and image auditing begin:

- DNS failures are preflighted and retried before the stage is marked as failed
- transient `Page.goto()` navigation errors use bounded retry/backoff instead of failing immediately
- the combined pipeline records a clearer `image_audit:*` warning when the page still cannot be resolved or loaded

This is why a missing image audit should now be treated as a crawl/navigation problem first, not as a Japanese-language OCR problem.

### Language routing and Japanese output

The crawler layer itself is not language-specific, but the image/OCR path now uses the submitted combined `lang` consistently:

- `lang=ja` is passed into OCR so Japanese and mixed-script images are scanned with Japanese-aware recognition
- Node receives the same `lang` for axe/custom-rule mapping, which localizes `criterion_name`, `reason`, and `suggested_fix`
- Python uses the same `lang` for shared `criterion_name` / `suggested_fix` lookups, while `reason` localization still depends on the individual auditor implementation

### TLS and expired certificates

As of `2026-04-13`, the crawler/browser contexts default to `ignore_https_errors=true` from the shared config. That means a bad target certificate no longer turns the standard frontend crawl flow into a generic Node `500` in the normal case.

Important caveats:

- This setting is meant for controlled auditing environments, not as a blanket security recommendation.
- If you explicitly disable it, Node now returns a clearer TLS-oriented error to clients instead of an opaque internal server error.

---

Legacy direct crawlers still share this contract:

```python
async def crawl() -> List[Dict[str, Any]]
def save_raw_json() -> None
```

They navigate the page using Playwright Chromium in headless mode, inject JavaScript to extract element metadata, and return a flat list of dicts. They never apply WCAG logic — that is the auditor's responsibility.

## AsyncImageCrawler

**File**: `ka11y/crawler/crawler.py`
**Crawls**: `<img>`, `<svg>`, `<button>`, background images, font icons (`<i>`, `<span>`)

### What it extracts per element

| Field | Description |
|-------|-------------|
| `src` | Image src (resolved absolute URL) |
| `alt` | `alt` attribute value |
| `aria_label` | `aria-label` |
| `aria_labelledby` | Referenced label text (resolved) |
| `aria_describedby` | Referenced description text |
| `aria_hidden` | `aria-hidden` attribute |
| `role` | `role` attribute |
| `natural_width/height` | Intrinsic image dimensions |
| `rendered_width/height` | `getBoundingClientRect()` dimensions |
| `in_button` | Whether the image is inside a `<button>` |
| `in_link` | Whether the image is inside an `<a>` |
| `link_href` | Parent link's `href` |
| `nearest_heading` | Text of the nearest ancestor heading |
| `surrounding_text` | 50 chars of surrounding text |
| `classification` | Result of `ClassifyAssets` cascade |

### Screenshot behaviour

After classification, the crawler screenshots each image to the appropriate category folder:

```
output_dir/
├── decorative/
├── informative/
│   ├── succinct_information/
│   └── logos/
├── functional/
│   ├── buttons/
│   ├── icons/
│   ├── logos/
│   └── images/
└── complex/
    └── charts/
```

### Image classification cascade

`ClassifyAssets` (in `ka11y/classifier/classfier.py`) runs a deterministic cascade:

| Step | Condition | Category |
|------|-----------|----------|
| 0 | `aria-hidden` or `role=presentation` | `decorative/presentational` |
| 1a | Inside `<button>` | `functional/buttons` |
| 1b | Logo keyword + inside real link | `functional/logos` |
| 1c | Chart keyword or parent chart class | `complex/charts` |
| 1d | Icon keyword + clickable | `functional/icons` |
| 1e | Inside real link or has click handler | `functional/images` |
| 2 | Standalone logo keyword | `informative/logos` |
| 3 | Standalone icon → has alt → `informative/icons`, no alt → `decorative/decorative` |
| 4 | alt present → `informative`, alt="" → `decorative`, alt absent → `decorative/missing_alt` |

## AsyncFormCrawler

**File**: `ka11y/crawler/forms_crawler.py`
**Crawls**: All form fields (`<input>`, `<textarea>`, `<select>`) inside `<form>` elements and implicit forms

> In the combined production path, `FormInputData` usually comes from the normalized universal snapshot, not a standalone `AsyncFormCrawler` browser session.

### What it extracts per field

| Field | Description |
|-------|-------------|
| `tag` | `INPUT`, `TEXTAREA`, or `SELECT` |
| `type` | Input type (`text`, `email`, `password`, etc.) |
| `element_id` / `element_name` | `id` or `name` attribute |
| `placeholder` | `placeholder` attribute |
| `aria_label` | Direct `aria-label` |
| `aria_labelledby` | Referenced label text |
| `label_text` | Text of associated `<label for="...">` |
| `wrapping_label_text` | Text of wrapping `<label>` |
| `required` | `required` attribute present |
| `aria_required` | `aria-required="true"` |
| `autocomplete` | `autocomplete` attribute value |
| `aria_describedby` | Referenced description element |
| `error_role` | Role of the describedby element |
| `error_aria_live` | `aria-live` value on error element |
| `html_snippet` | Outer HTML (truncated to 600 chars) |

### JavaScript extraction

The crawler injects a single `EXTRACT_JS` script that traverses all forms and implicit forms, resolves label associations, and returns the complete field metadata in one `page.evaluate()` call.

## InteractiveElementCrawler

**File**: `ka11y/crawler/interactive_crawler.py`
**Crawls**: `<button>`, `<a>`, `<input type="submit/button/reset/image">`, elements with `role` in `{button, link, menuitem, tab, option, treeitem, gridcell}`

> In the combined production path, `InteractiveElementData` usually comes from the normalized universal snapshot, with `selector`, `element_ref_id`, and `frame_path` attached for provenance.

### What it extracts per element

| Field | Description |
|-------|-------------|
| `tag` | Element tag name |
| `role` | ARIA role (explicit or implicit) |
| `visible_label` | Visible text content (stripped) |
| `aria_label` | `aria-label` attribute |
| `aria_labelledby` | Referenced label text (resolved) |
| `title` | `title` attribute |
| `accessible_name` | Computed accessible name (AccName 1.1 algorithm) |
| `element_id` | `id` attribute |
| `input_type` | For `<input>`, the `type` attribute |

### Accessible name computation

The crawler computes `accessible_name` client-side following a simplified AccName 1.1 priority order:

1. `aria-labelledby` (resolved text)
2. `aria-label`
3. `value` (for `<input type="submit/button">`)
4. `alt` (for `<input type="image">`)
5. Element text content
6. `title`

This mirrors the computation a browser or assistive technology would perform.

## MovingContentCrawler

**File**: `ka11y/crawler/moving_content_crawler.py`
**Crawls**: Auto-playing video, animated GIFs, CSS/WAAPI animations, JavaScript carousels, `<marquee>`, `<blink>`

> In the combined production path, `MovingContentData` is normalized from the universal snapshot so that same-origin frame traversal and open shadow traversal are available to `2.2.2`.

### Detection strategies

| Type | Detection method |
|------|-----------------|
| `video_autoplay` | `<video>` with `autoplay` attribute |
| `animated_gif` | `<img>` whose `src` ends in `.gif` |
| `css_animation` | `document.getAnimations()` — running WAAPI or CSS animations with `iteration: Infinity` |
| `carousel_autoplay` | Class/data-attribute detection for Bootstrap, Swiper, Slick, Owl, Flickity, Glide, Splide |
| `marquee` | `<marquee>` elements |
| `blink` | `<blink>` elements |

### Production-only metadata used by the combined pipeline

| Field | Meaning |
|------|---------|
| `duration_known` | Distinguishes genuinely short media from cases where duration could not be determined |
| `applicability_exception` | Used for essential exceptions such as `loading_indicator` in `2.2.2` |
| `selector` | Composed selector for evidence and deduplication |
| `element_ref_id` | Stable lookup key into the universal snapshot sidecar |
| `frame_path` | Same-origin iframe provenance |

### Why this goes beyond axe-core

axe-core only flags `<blink>` and `<marquee>`. It does not detect:
- CSS animations with infinite loops
- JavaScript carousel libraries
- `<video autoplay>`
- Animated GIFs

The `axe_would_catch` boolean in each record lets you filter down to novel detections.

## TargetSizeCrawler

**File**: `ka11y/crawler/target_size_crawler.py`
**Crawls**: All interactive elements: `<button>`, `<a>`, `<input>`, `<select>`, `<textarea>`, ARIA role equivalents

> In the combined production path, `TargetSizeData` is normalized from the universal snapshot, so same-origin frame content and shadow-root content can reach the auditor through the existing model.

### What it extracts per element

| Field | Description |
|-------|-------------|
| `rendered_width_px` | `getBoundingClientRect().width` |
| `rendered_height_px` | `getBoundingClientRect().height` |
| `padding_top/right/bottom/left` | Computed padding from `getComputedStyle` |
| `is_inline_exception` | `<a>` in inline context (WCAG 2.5.8 exception 1) |
| `is_ua_controlled_exception` | Native checkbox/radio with `appearance: auto` (exception 4) |
| `is_offset_exception` | Undersized target has sufficient spacing (exception 5) |
| `required_offset_x_px` / `required_offset_y_px` | Required clear area around target based on size deficit |
| `nearest_target_gap_x_px` / `nearest_target_gap_y_px` | Nearest neighboring target gap along each axis |

### Exception detection

**Exception 1 — Inline**: An `<a>` element is inline when its `display` is `inline` and it is not the sole interactive element on its line. The crawler approximates this by checking `getComputedStyle().display === 'inline'`.

**Exception 4 — UA-controlled**: A `<input type="checkbox">` or `<input type="radio">` where `getComputedStyle().appearance` is `auto` or `checkbox`/`radio` (the browser controls the size).

**Exception 5 — Offset**: For undersized targets, the crawler computes required offset `((24 - width)/2, (24 - height)/2)`, inflates the target bounds by that amount, and marks `is_offset_exception=true` when no neighboring target intersects the inflated box.
