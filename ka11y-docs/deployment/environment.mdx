## ka11y-node

| Variable | Default | Required | Description |
|----------|---------|----------|-------------|
| `NODE_ENV` | `development` | No | Set to `production` to disable dev logging |
| `PORT` | `3000` | No | Port the Express server listens on |
| `AXE_TIMEOUT_MS` | `60000` | No | Per-page axe-core scan timeout (milliseconds) |
| `CUSTOM_CHECKS_TIMEOUT_MS` | `30000` | No | Per-page budget (ms) for the Node custom checks (focus-visible, on-focus, keyboard-trap, etc.), split 60/40 between static and interactive phases. Was `90000`; dropped 2026-05-29 after profiling showed the interactive phase was the dominant per-page cost. Raise this on sites that need exhaustive interactive coverage; lower it on shallow scans where speed matters more than the tail of focus-checks. See [Stage timing](/internals/stage-timing) for which phase hit the cap. |
| `FLAT_CRAWL_BUDGET_MS` | `255000` | No | Overall multi-page crawl budget (ms) for `/api/v1/analyse-url-flat`. Must stay below the Python `_call_node_flat` HTTP timeout (300 s). Ignored in snapshot-fed mode (when Python sends `discoveredUrls`) — Node then audits exactly the snapshot's pages without time-based clipping. |
| `FLAT_PER_PAGE_MS` | `120000` | No | Per-page hard cap (ms) inside the flat crawl loop, clamped to the remaining overall budget. |
| `BODY_LIMIT` | `10mb` | No | Express request body size limit |
| `PUPPETEER_EXECUTABLE_PATH` | `/usr/bin/chromium` | No | Path to the Chromium binary (auto-set in Dockerfile) |
| `PUPPETEER_SKIP_DOWNLOAD` | `true` | No | Prevents Puppeteer from downloading its own Chromium (auto-set in Dockerfile) |

### Example `.env` (Node)

```bash
NODE_ENV=production
PORT=3000
AXE_TIMEOUT_MS=90000
BODY_LIMIT=10mb

# Tune custom-check coverage vs. throughput.
# 30s default keeps multi-page crawls bounded; raise on sites that need
# exhaustive interactive focus-check coverage.
CUSTOM_CHECKS_TIMEOUT_MS=30000
```

## ka11y-python

| Variable | Default | Required | Description |
|----------|---------|----------|-------------|
| `NODE_BASE_URL` | `http://localhost:3000` | Yes (in Docker) | Base URL used by ka11y-python to reach the ka11y-node service |
| `PYTHONUNBUFFERED` | — | Recommended | Set to `"1"` for real-time log output in Docker |
| `KA11Y_MAX_BROWSERS` | `2` | No | Maximum concurrent Playwright context leases from `BrowserPool`. Bounds Chromium memory. See `ka11y-python/ka11y/crawler/browser_pool.py`. |
| `KA11Y_MAX_CONCURRENT_JOBS` | `4` | No | Maximum concurrent `_run_job()` background tasks. Excess jobs sit in `status="queued"` until a slot frees. See `ka11y-python/ka11y/api/v1/combined/runner.py`. |
| `KA11Y_JOB_TIMEOUT_SECONDS` | `1800` | No | Outer audit budget. Bounds the top-level `asyncio.gather` over axe + Python branches. On timeout both branches are cancelled and a scrubbed error is returned. |
| `KA11Y_HEAVY_STAGE_CONCURRENCY` | `2` | No | Process-wide cap on concurrent browser-heavy stages (`image_audit`, `rendered_layout_audit`). Excess stages park on a semaphore — the queue wait does **not** count against `_STAGE_TIMEOUT_SECONDS`. See `ka11y-python/ka11y/api/v1/combined/stages.py`. |
| `KA11Y_STAGE_TIMING_DIR` | `ka11y-python/logs/timings/` | No | Override the directory where per-(page, stage, rule) timing files (`<run_id>.jsonl` + `<run_id>.summary.log`) are written. See [Stage timing](/internals/stage-timing). |
| `KA11Y_STAGE_TIMING_DISABLE` | — | No | Set to `1` / `true` to skip all stage-timing writes. Existing `crawler_timings.log` and `run_timings.log` are unaffected. |

### Example `.env` (Python)

```bash
NODE_BASE_URL=http://node:3000
PYTHONUNBUFFERED=1

# Concurrency caps — tune for the host's memory budget.
# Chromium ≈ 300 MB per process; one process per pool, multiple contexts per process.
KA11Y_MAX_BROWSERS=2
KA11Y_MAX_CONCURRENT_JOBS=4
KA11Y_JOB_TIMEOUT_SECONDS=1800
KA11Y_HEAVY_STAGE_CONCURRENCY=2

# Low-level per-(page, stage, rule) timing logs. Comment out the DISABLE line
# to opt in; override the directory if you want logs outside the repo.
# KA11Y_STAGE_TIMING_DIR=/var/log/ka11y/timings
# KA11Y_STAGE_TIMING_DISABLE=1
```

<Note>
  Inner stage timeouts are hardcoded (not env-tunable) because they bound individual auditors with semantics that depend on each rule: `_STAGE_TIMEOUT_SECONDS=600` (per-stage in `stages.py`), `_SCENARIOS_TIMEOUT_SECONDS=300` (rendered-layout 7-way fan-out in `rendered_layout_crawler.py`).
</Note>

<Note>
  In Docker Compose the Python container resolves `node` by Docker's internal DNS — use `http://node:3000`. For local development outside Docker use `http://localhost:3000`.
</Note>

### Environment Matrix & Connectivity

| Scenario | `NODE_BASE_URL` (Python) | Browser/Frontend |
|----------|--------------------------|-------------------|
| **Full Docker Compose** | `http://node:3000` | Calls `/api/*` (proxied to Python) |
| **Host-run Python + Node** | `http://localhost:3000` | Calls `http://localhost:8000/api/*` |
| **Hybrid (Container Python)** | `http://host.docker.internal:3000` | Calls `/api/*` |

<Warning>
  `node:3000` is a Docker-internal hostname. The browser cannot resolve it. Always ensure the frontend calls only the Python API origin (or a proxy).
</Warning>

## ka11y-frontend

The frontend is a static React build served by nginx. There are no runtime environment variables — all API calls go to `/api/*` which nginx proxies to the Python service.

Build-time Vite variables can be set in `.env.local`:

```bash
# ka11y-frontend-sdk/.env.local (development only)
VITE_API_URL=http://localhost:8000
```

That value is only used by the Vite dev server proxy. The production nginx container ignores it and proxies `/api/*` to `python:8000` internally.

## Docker Compose env block reference

The `docker-compose.yml` at the repo root sets these variables for each service:

```yaml
services:
  node:
    environment:
      NODE_ENV:       production
      PORT:           "3000"
      AXE_TIMEOUT_MS: "60000"
      BODY_LIMIT:     "10mb"

  python:
    environment:
      NODE_BASE_URL:    "http://node:3000"
      PYTHONUNBUFFERED: "1"
```

---

## Using a `.env` file with Docker Compose

Create a `.env` file in the repo root to override any value without editing `docker-compose.yml`:

```bash
# .env  (repo root)
AXE_TIMEOUT_MS=90000
NODE_BASE_URL=http://my-node-host:3000
```

Docker Compose automatically loads `.env` from the same directory as `docker-compose.yml`.

## Secrets and sensitive values

ka11y-python calls `load_dotenv()` at startup (`ka11y/main.py`), so you can place a `.env` file in the `ka11y-python/` directory:

```bash
# ka11y-python/.env
NODE_BASE_URL=http://node:3000
```

Do **not** commit `.env` files to version control. Add them to `.gitignore`:

```
.env
.env.local
.env.production
```

## Playwright / Chromium environment

These are set automatically by the Python Dockerfile and do not need to be configured manually:

| Variable | Value | Purpose |
|----------|-------|---------|
| `PLAYWRIGHT_BROWSERS_PATH` | `/ms-playwright` | Where `playwright install` stores browsers |

Playwright's Chromium is installed during `docker compose build` via:

```dockerfile
RUN poetry run playwright install chromium --with-deps
```

This downloads Chromium into the image layer — no network access is needed at runtime.
