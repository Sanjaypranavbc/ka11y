description: "POST /api/v1/combined/ · GET /api/v1/combined/{job_id} · GET /api/v1/combined/{job_id}/stream · GET /api/v1/combined/{job_id}/image"

The combined endpoint is the **primary API**. It runs axe-core (Node) and all Python auditors in parallel, merges findings into a single flat list, and exposes job status via REST polling and Server-Sent Events streaming. When OCR is enabled, a `contrast_report` is attached to the result and per-image files can be retrieved via the image endpoint.

If you want a **full production-style run**, omit the optional `run_*` booleans and let the defaults stay `true`. Disabling flags is useful for targeted debugging, but it is not the same as a full-stack audit.

---

## Submit an audit

<ParamField body="url" type="string" required>
  Fully-qualified URL to audit (e.g. `https://example.com`).
</ParamField>

<ParamField body="max_depth" type="integer" default="0">
  How many link-levels deep to crawl. `0` audits only the submitted URL. `1` follows internal links one level deep. Keep low (≤ 2) to avoid long runtimes.
</ParamField>

<ParamField body="wcag_level" type="string" default="AAA">
  Conformance target: `"A"` | `"AA"` | `"AAA"`. Controls which axe-core tags are used and filters Python findings by WCAG level. Use `AAA` if you want `1.4.6 Contrast (Enhanced)` in the final finding arrays; lowering the level hides higher-level findings.
</ParamField>

<ParamField body="lang" type="string" default="en">
  Result language for localized WCAG names and suggested fixes. Use `"ja"` for Japanese (`"en"` and `"de"` are also supported). Unsupported values fall back to English. Default result language is English.
</ParamField>

<ParamField body="run_ocr" type="boolean" default="true">
  Run EasyOCR on crawled images to detect embedded text and compute image-text contrast. This powers Python findings for `1.4.3`, `1.4.6`, and the OCR-backed parts of `1.1.1`, `1.4.5`, and `1.4.11`.
</ParamField>

<ParamField body="run_image_audit" type="boolean" default="true">
  Enable the image auditor. This stage emits Python findings for `1.1.1 Non-text Content`, `4.1.2 Name, Role, Value` on functional images, `1.4.5 Images of Text`, and `1.4.11 Non-text Contrast` when applicable.
</ParamField>

<ParamField body="run_form_audit" type="boolean" default="true">
  Enable the WCAG 3.3.1 / 3.3.2 form auditor.
</ParamField>

<ParamField body="run_label_in_name_audit" type="boolean" default="true">
  Enable the WCAG 2.5.3 label-in-name auditor.
</ParamField>

<ParamField body="run_pause_stop_hide_audit" type="boolean" default="true">
  Enable the WCAG 2.2.2 pause/stop/hide auditor.
</ParamField>

<ParamField body="run_target_size_audit" type="boolean" default="true">
  Enable the WCAG 2.5.8 target-size auditor.
</ParamField>

<ParamField body="run_resize_text_audit" type="boolean" default="true">
  Enable the WCAG 1.4.4 Resize Text rendered-layout auditor. Simulates 200% font scaling and checks for clipped or overflowing text.
</ParamField>

<ParamField body="run_reflow_audit" type="boolean" default="true">
  Enable the WCAG 1.4.10 Reflow rendered-layout auditor. Renders the page at 320 px width and checks for horizontal scrolling.
</ParamField>

<ParamField body="run_text_spacing_audit" type="boolean" default="true">
  Enable the WCAG 1.4.12 Text Spacing rendered-layout auditor. Injects WCAG-mandated spacing overrides and checks for newly clipped text elements.
</ParamField>

<ParamField body="run_orientation_audit" type="boolean" default="true">
  Enable the WCAG 1.3.4 Orientation rendered-layout auditor. Renders the page in portrait and landscape viewports and checks for orientation-lock indicators.
</ParamField>

<ParamField body="run_hover_focus_content_audit" type="boolean" default="true">
  Enable the WCAG 1.4.13 Content on Hover or Focus rendered-layout auditor. Simulates hover interactions on tooltip/dropdown triggers and checks dismissibility and hoverability.
</ParamField>

<ParamField body="run_focus_not_obscured_min_audit" type="boolean" default="true">
  Enable the WCAG 2.4.11 Focus Not Obscured (Minimum) rendered-layout auditor. Tabs through up to 100 focusable elements and checks whether any is entirely hidden by a fixed/sticky overlay.
</ParamField>

<ParamField body="run_focus_not_obscured_enh_audit" type="boolean" default="true">
  Enable the WCAG 2.4.12 Focus Not Obscured (Enhanced) rendered-layout auditor. Same focus traversal as 2.4.11 but fails on any meaningful overlap (≥ 10%) rather than full occlusion.
</ParamField>

```bash cURL
    "lang": "ja",

    "run_form_audit": true,

    "run_target_size_audit": true,

    "run_hover_focus_content_audit": true,
    "run_focus_not_obscured_min_audit": true,
```

### Full-stack request with all rule families enabled

The simplest way to keep every stage enabled is to send only the core request fields and omit the optional booleans:

```bash cURL
curl -X POST http://localhost:8000/api/v1/combined/ \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com",
    "wcag_level": "AAA",
    "lang": "en",
    "max_depth": 0
  }'
```

That uses the current defaults:

- `run_ocr = true`
- `run_image_audit = true`
- `run_form_audit = true`
- `run_label_in_name_audit = true`
- `run_media_audit = true`
- `run_pause_stop_hide_audit = true`
- `run_target_size_audit = true`
- `run_resize_text_audit = true`
- `run_reflow_audit = true`
- `run_text_spacing_audit = true`
- `run_orientation_audit = true`
- `run_hover_focus_content_audit = true`
- `run_focus_not_obscured_min_audit = true`
- `run_focus_not_obscured_enh_audit = true`
- `run_sensory_audit = true`

Set `lang` to `"ja"` in the submit payload:


## Stream job events (SSE)

```
GET /api/v1/combined/{job_id}/stream
```

Returns a `text/event-stream` response. Connect with `EventSource` in the browser or `curl -N` in a terminal.

<Note>
  Connect **immediately after** submitting the job. If you connect after the job has already completed or failed, the stream sends a single terminal event and closes.
</Note>

### Event types

| Event | Payload | When |
|-------|---------|------|
| `stage_start` | `{ stage_name, started_at }` | A stage begins executing |
| `stage_complete` | `{ stage_name, completed_at, findings_count }` | A stage finishes successfully |
| `stage_error` | `{ stage_name, error }` | A stage fails (non-fatal) |
| `job_state` | `{ current_stage, stages[] }` | Sent once on late connect if job is already running |
| `job_complete` | `{ job_id, summary }` | Job finished (poll REST for full `result`) |
| `job_failed` | `{ job_id, error }` | All sources failed |

Heartbeat comment lines (`": keepalive"`) are sent every 25 seconds to prevent proxy timeouts.

<RequestExample>
```bash Terminal
curl -N http://localhost:8000/api/v1/combined/b5ea3ea7-.../stream
```

```javascript Browser
const es = new EventSource(`/api/v1/combined/${jobId}/stream`);

es.addEventListener("stage_start", e => {
  const { stage_name, started_at } = JSON.parse(e.data);
  console.log(`▶ ${stage_name} started`);
});

es.addEventListener("stage_complete", e => {
  const { stage_name, findings_count } = JSON.parse(e.data);
  console.log(`✓ ${stage_name} — ${findings_count} findings`);
});

es.addEventListener("job_complete", async e => {
  es.close();
  const { job_id } = JSON.parse(e.data);
  const res = await fetch(`/api/v1/combined/${job_id}`);
  const full = await res.json();
  console.log(full.result.summary);
});
```
</RequestExample>

## Serve a job image

```
GET /api/v1/combined/{job_id}/image?path={encoded_path}
```

Returns a crawled image file as a binary response (`image/jpeg`, `image/png`, etc.). This endpoint is used by the frontend Image Visualiser tab to render contrast report images inline.

The `path` query parameter must be the **exact filesystem path** stored in `contrast_report.images[].path` for the given job. Paths that are not associated with the job are rejected with `403 Forbidden`.

<Note>
  The `image_url` field injected into each `ContrastImageDetail` is a pre-built, ready-to-use relative URL — consume it directly; do not construct image URLs manually.
</Note>

### Security model

- Only paths present in `contrast_report.images` for the requested `job_id` are served (job-scoped whitelist).
- The file must exist on the server filesystem at the recorded path.
- No directory traversal is possible because the path is validated against the whitelist before any filesystem access.

<ResponseExample>
```http HTTP 200
Content-Type: image/jpeg
Content-Length: 48392

<binary image data>
```

```json HTTP 403
{ "detail": "Image path not associated with this job." }
```

```json HTTP 404
{ "detail": "Image file not found on server." }
```
</ResponseExample>

## Stage names reference

| `stage_name` | WCAG SC | Description |
|---|---|---|
| `axe_core` | multiple | Node.js / axe-core WCAG scan |
| `image_audit` | 1.1.1 | Image alt-text check (OCR-backed) |
| `form_audit` | 3.3.1, 3.3.2 | Form label and error message check |
| `label_in_name` | 2.5.3 | Accessible name must contain visible label |
| `pause_stop_hide` | 2.2.2 | Auto-playing / animated content check |
| `target_size` | 2.5.8 | Touch target minimum size check |
| `rendered_layout_audit` | 1.3.4, 1.4.4, 1.4.10, 1.4.12, 1.4.13, 2.4.11, 2.4.12 | Rendered-layout checks via Playwright (resize, reflow, text spacing, orientation, hover/focus, focus obscured) |
